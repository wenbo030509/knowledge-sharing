## TL;DR

- **整体定位**：三步流程是一次"诊断 → 造数据 → 模仿"的**靶向 SFT**，不是 RL 训练。
- **数据形态**：`(视频, prompt, response)` 三元组是 SFT 正样本，loss 只在 response token 上计算。
- **Rollout 实质**：行为引导 Rollout 是 SFT 前的引导式数据合成（拒绝采样），与 RLHF / DPO / GRPO 处于不同环节。
- **收益归因**：覆盖题 +2.8 是直接效果，全量 +0.5 受覆盖率稀释，WildClaw +2.3 证明学到的是可泛化能力。
- **对质检工作的意义**：搞清消费链路后，**"什么是好数据"有了下游定义**——质检标准（证据充分、难度对齐、格式统一）正是 SFT 正样本的质量约束，两端是同一套语言。

## 三、坐标系：VLM 视频理解与后训练范式

视频进入 VLM 后不是被"看成连续画面"，而是经过一条固定链路：mp4 先抽帧（均匀采样或按帧率取关键帧，帧数是 token 预算与信息保留之间的权衡），每帧经视觉编码器（ViT，图像切 patch + 高分辨率窗口注意力）编码为视觉 token，帧间通过时序注意力与时序位置编码对齐（Qwen2.5-VL 一类模型把位置编码与绝对时间对齐），最后视觉 token 与文本 prompt 的 token 拼接，送入 LLM 解码器自回归生成 response。

大模型后训练有三种基本范式：

| 范式 | 数据形态 | 学习方式 |
|------|----------|----------|
| SFT | 正样本 | 离线模仿学习 |
| DPO | 成对偏好数据 | 直接优化相对概率 |
| RL（PPO/GRPO） | prompt + 奖励 | 在线采样轨迹，用奖励信号更新策略 |

算法侧这次明确止于 SFT——前两步（轨迹对比、行为引导 Rollout）都是在为 SFT 准备高质量正样本，而不是独立的训练阶段。

## 四、三元组：SFT 的监督信号长什么样

数据侧交付的 `(视频, prompt, response)` 三元组，在训练管线里三个组成部分的命运完全不同：

| 组成 | 原始形态 | 进入模型后的形态 | 训练时的角色 |
|------|----------|------------------|--------------|
| video | mp4，按时长、清晰度、相关性、去重过滤后保留 | 抽帧 → ViT 编码为视觉 token 序列，带时序位置编码 | 输入条件，loss 掩码 |
| prompt | 针对该视频设计的问题/指令，必须依赖画面才能回答 | 分词为文本 token，套 chat template | 输入条件，loss 掩码 |
| response | 人工编写的高质量参考回答，CoT 结构清晰、格式统一 | 分词为文本 token，接在视觉与 prompt 之后 | 唯一计算 loss 的监督目标 |

四维度质检不是交付前的形式审查，每一维都对应一个具体的训练风险：

| 质检维度 | 拦住的训练风险 |
|----------|----------------|
| 内容准确性 | 标签噪声：错误 response 的每个 token 都在产生错误梯度，SFT 对标签噪声几乎零容忍 |
| 回答完整性 / 不可跳步 | 过程缺陷：答案对但推理断链的样本，会把"跳步路径"当作正确示范教给模型 |
| 格式规范 | 格式漂移：样本间结构不一致，会稀释模型对目标输出格式的概率质量 |
| 视频匹配度 | 语言捷径：不看视频也能答对的弱样本，会教会模型绕过视觉编码器、纯靠语言先验作答 |

这批数据的另一个关键属性是"**同类别属性**"：视频不是随便采的，而是对准已有 VQA 例题的题型类别定向采集，最终覆盖内部评测 161 题中的 72 题。这相当于把训练数据当成"错题本"来投——模型在哪类题上弱，就补哪类题的新视频，而不是均匀铺量。

## 五、Technical Anatomy 主题 1：模型轨迹对比——训练前的错误诊断

**概念**：在用数据微调之前，先拿待微调的 base 模型对全部已标注 prompt 跑一遍推理，保存模型的完整输出轨迹（含思维链），再与人工 response 逐条对比。这一步不更新任何参数，产出物是一张"错误地图"。

**技术实现分三层**：

```text
① 可复现推理：固定解码配置（低温或贪心解码），用同一推理引擎对全量
   prompt 批量推理，输出完整 CoT 而非只有最终答案。
② 两层对比：
   ├── 结果层：判最终答案对错（答案抽取 + 规则匹配或 judge 模型判定）
   └── 过程层：对齐推理链，定位偏离发生在第几步——是漏看了某个时间段
       的画面、时序先后颠倒，还是因果推理跳步。
③ 错误归类聚合：按题型（时序理解 / 画面描述 / 动作识别）和错误环节
   （感知层 / 推理层 / 格式层）聚合统计，得到模型错误的分布热力。
```

这张错误地图决定后续两件事：**数据补在哪里**（本轮 72 题优先对准薄弱题型）和 **Rollout 要规范什么行为**（比如发现模型普遍跳过时序推理，就在行为引导里强制"先陈述关键帧观察、再推理"）。

**为什么这步不可省**：SFT 是 off-policy 模仿学习，只给正样本，模型并不知道"自己现在错在哪"。轨迹对比把当前策略 π_θ 与目标分布之间的 gap 显式定位出来，让后续数据投入有的放矢，而不是盲目堆量。

> 💭 猜测：以上为结合算法反馈的机制还原，具体对比脚本、错误归类口径以算法侧实现为准。

## 六、Technical Anatomy 主题 2：行为引导 Rollout——不是 RL，是 SFT 数据合成

RL 语境里的 rollout 指"用当前策略从头采样一条完整轨迹"。但本项目 rollout 的产物最终进了 SFT 训练集，所以它的工程实质是**引导式数据合成**——业界称为拒绝采样（rejection sampling）或 STaR 式自我改进，而不是一次 RL 参数更新。

**机制分四步**：

```text
① 行为注入：通过 system prompt 或少量 few-shot 示范规定 response 的
   行为模式——思维链先陈述关键帧观察（可带时间戳），再做时序/因果
   推理，最后给结论；输出字段与格式固定。
② 采样：用模型（更强的教师模型或当前模型）在 temperature > 0 下对
   同一 prompt 采样多条 response，制造多样性。
③ 筛选（拒绝采样）：只有"答案正确 且 过程合规（不跳步、因果明确、
   格式规范）"的轨迹保留；答案对但路径错的丢弃。这就是反馈里
   "以正确路径答对"的含义——过程监督而非只看结果。
④ 混入训练集：入选轨迹与人工三元组混合，共同构成 SFT 正样本。
```

算法反馈中提到的 RLHF / DPO / GRPO 与这一步的关系，需要严格区分：

| 方法 | 数据需求 | 在线采样 | 优化目标 |
|------|----------|----------|----------|
| SFT | 正样本 response | 否 | 最大化 gold response 的似然 |
| RLHF/PPO | prompt + 奖励模型 | 是 | 最大化 RM 奖励，加 KL 约束防跑偏 |
| DPO | 偏好对 (chosen, rejected) | 否 | 直接拉大 chosen 与 rejected 的相对概率 |
| GRPO | prompt + 可验证奖励 | 是（同题 G 条） | 组内奖励归一化为 advantage，PPO 式 clip 更新 |

GRPO 的核心直觉是：对同一 prompt 采样 G 条 response，用规则/验证器给每条打奖励 r，再算组内相对优势 $\hat{A}_i=(r_i-\mathrm{mean})/\mathrm{std}$，比平均好的轨迹提概率、差的降概率，且不需要训练 critic 网络。DPO 则完全不采样，用一个闭式损失把"chosen 比 rejected 好"的偏好直接写进策略。

**为什么本项目止步于 Rollout + SFT 而不直接上 RL**：开放型视频 VQA 没有廉价可验证的奖励——答案对错往往要 judge 模型甚至人工判定，RL 的奖励信号成本很高；且 RL 普遍需要 SFT 冷启动，否则初始采样质量太差无法学习。业界主流 VLM recipe（Qwen2.5-VL、Seed-VL 等）同样是 SFT 阶段大量使用拒绝采样轨迹、用奖励模型过滤 rollout，RL 阶段才上可验证奖励。本轮数据规模下，引导 rollout + SFT 是性价比最高的路径。

这一步与数据侧的质检标准是同一套语言：response 要求"压缩充分精简、不可跳步、因果关系明确"，正是 rollout 筛选的保留条件和 response 的写作规范——compressed-CoT 数据教给模型的是"短且路径正确"的推理链，而不是冗长但正确的推理链。

> 💭 猜测：采样条数、筛选阈值、教师模型选择等具体配置以算法侧实验为准。

## 七、Technical Anatomy 主题 3：SFT 监督微调——训练目标与损失函数

**训练目标**：给定视觉 token 序列 v 和 prompt x，让模型对人工 response y 的条件概率最大化。损失是 response token 上的平均负对数似然：

$$\mathcal{L}_{SFT}=-\frac{1}{|y|}\sum_{t=1}^{|y|}\log p_\theta(y_t\mid v,x,y_{<t})$$

**损失掩码（loss mask）是关键细节**：视觉 token v 和 prompt x 只作为条件出现在上下文里，它们的预测损失被掩掉，梯度只从 response token 回传。原因很直接——视频和问题是"给定的输入"，模型不需要学习"生成视频"或"生成问题"。训练配置上，视觉编码器通常冻结或用显著更小的学习率，可训练主体是 LLM（全参微调或 LoRA）；chat template 必须与推理时严格一致。

**工程实践上还有两个防翻车点**：

```text
├── 小数据量时 epoch 一般只跑 1–2 轮（多轮必然过拟合，loss 早早收敛
│   后继续训反而损害泛化）
└── 按比例混入通用指令数据，防止模型在垂类数据上"降智"（灾难性遗忘）
```

**CoT 为什么能被 SFT 学会**：teacher forcing 机制下，模型在每个推理步 token 上都被要求"基于视频观察 + 此前推理"预测下一步，正确推理路径的整条序列概率被反复抬高；rollout 筛选又保证了被模仿的路径本身是对的。于是模型学到的不是某个答案，而是 $p(\text{下一步推理}\mid\text{观察},\text{已有推理})$ 这样一个行为分布。

**SFT 的边界**：它只抬高正样本的似然，不显式压低坏样本的概率——不教模型"好答案比坏答案好在哪"，那是 DPO/RL 的工作。因此正样本质量（人工质检 + rollout 筛选）直接决定 SFT 的天花板。**这句话就是"质检标准 = SFT 天花板"的算法版表述。**

## 八、评测：两轮对照设计、rubric 打分与指标解读

### 8.1 两轮对照评测：SFT 前基线 vs SFT 后

评测采用标准 before/after 对照设计：第一轮用未做任何微调的初始 base 模型，第二轮用 rollout 数据 SFT 后的模型；两轮在完全相同的三套 benchmark 上推理、按完全相同的 rubric 打分，再作差得到提升量。整个对照中唯一变量是模型权重。

| 维度 | 第一轮（基线） | 第二轮（SFT 后） |
|------|----------------|------------------|
| 模型 | 初始 base 模型，未经过本轮数据微调 | 人工三元组 + rollout 入选轨迹 SFT 后的模型 |
| 评测集 | 补充拓展题目 / ClawEval / WildClaw 三套 | 与第一轮完全相同的题目和视频 |
| 推理配置 | 固定解码配置（温度、抽帧策略、prompt 模板） | 与第一轮严格一致，禁止换推理链路 |
| 打分 | 按统一 rubric 评分 | 同一套 rubric、同一 judge 模型版本 |
| 产出 | 基线分数 + 全部错误 case | 第二轮分数，逐题与基线作差得 delta |

delta 的可信度完全依赖控制变量：如果两轮之间换了抽帧数、解码温度或 judge 版本，+0.5 / +2.3 / +2.8 里就混入了与训练无关的扰动，归因不成立。

### 8.2 三套 benchmark 各自回答什么问题

| Benchmark | 构成 | 在对照中的作用 |
|-----------|------|----------------|
| 补充拓展题目 | 围绕已有 VQA 例题、按同类别属性拓展出的 held-out 题目 | 验证靶向题型"有没有被学会"，考的是同类别新题而非原题 |
| ClawEval | 内部全量视频 VQA 集，共 161 题，其中 72 题被训练数据覆盖 | 全量净收益 +0.5；覆盖子集 +2.8；未覆盖的 89 题同时充当降智监控——分数不应显著下滑 |
| WildClaw | 真实场景视频构成的"野外"泛化集，与训练视频严格隔离 | 跨分布泛化收益 +2.3，无法用记忆训练视频解释 |

> 📌 待确认："补充拓展题目"的具体题量、与 ClawEval 161 题及 72 题覆盖口径的对应关系，以算法侧评测配置为准。

### 8.3 rubric 打分：开放型 VQA 怎么判分

视频 VQA 多为开放作答，没有唯一标准答案，不用精确匹配判分。每条 response 按 rubric（评分细则）打分，维度通常包括：最终答案是否正确、关键画面与时序信息是否覆盖、因果推理是否成立、格式是否合规。工程实现一般是"答案抽取 + 规则校验 + judge 模型按 rubric 评分"，聚合为题均得分。两轮必须锁死同一套 rubric 和同一个 judge 版本——评分标准一旦漂移，delta 就不可比。

**第一轮推理的双重用途**：base 模型在 benchmark 上的推理结果，一方面产出基线分数，另一方面就是第一步"模型轨迹对比"的输入——同一批错误 case 既算基线、又当训练靶点。一次推理，基线评测与错误诊断两用，这也是轨迹对比必须在 SFT 前完成的原因。

**防数据泄漏是这套对照成立的前提**：SFT 用的是同类别属性的新采集视频，与三套 benchmark 的视频严格不重叠，WildClaw 更是完全 held-out。因此 WildClaw 上的 +2.3 不能用"模型记住了训练视频"解释，只能归因于行为引导 Rollout 规范出的解题路径发生了真实泛化。

### 8.4 三个数字的归因

| 评测项 | 口径 | 提升 | 怎么读 |
|--------|------|------|--------|
| ClawEval | 内部全量视频 VQA 评测集，共 161 题，覆盖多类题型 | +0.5 | 全量平均分，被 89 道未覆盖题稀释 |
| WildClaw | 真实场景视频构成的"野外"泛化评测集，考察方向与本轮数据对齐 | +2.3 | 同类能力在未见视频上的泛化收益 |
| 72 题子集 | ClawEval 中被训练数据直接覆盖的题目 | +2.8 | 靶向数据的直接效果，方向有效的硬证据 |

三个数字放在一起，归因链非常清楚：

```text
├── +2.8（覆盖子集）：数据直接覆盖的题型提升最大，证明三元组形态、
│   质检口径和训练链路本身有效。
├── +0.5（ClawEval 全量）：161 题中 89 题没有数据覆盖、分数基本不动，
│   把 72 题上的高收益拉低到全量均值。瓶颈是覆盖率（约 45%），
│   不是数据质量。
└── +2.3（WildClaw）：最值得注意的数字。训练数据是"同类别属性的
    新视频"而非评测原题，模型无法靠背答案获益；WildClaw 又只考
    这个方向、没有未覆盖题型稀释，收益更纯。它说明行为引导 Rollout
    规范出的解题路径是可迁移的行为模式，在真实分布的视频上依然成立。
```

| **PM 视角** | 三步流程 = 一条"诊断 → 造数据 → 模仿"的靶向优化闭环；交付的数据不是终点，而是这条闭环的原料。理解闭环让我能回答"我交付的数据产生了什么价值"——覆盖子集 +2.8 就是价值凭证。 |

## 十一、面试官追问准备

```text
Q1：行为引导 Rollout 是 RL 吗？
→ 不是。它的产物进了 SFT 训练集，工程实质是拒绝采样/STaR 式数据合成，
   没有奖励信号驱动的参数更新。RL 的 rollout 是在线采样 + 奖励更新策略。

Q2：为什么不直接上 RL？
→ 开放 VQA 没有廉价可验证奖励（要 judge/人工判定，成本高）；且 RL 需要
   SFT 冷启动。本轮数据规模下 rollout + SFT 性价比最高。业界主流 VLM
   recipe 也是 SFT 阶段用拒绝采样、RL 阶段才上可验证奖励。

Q3：loss mask 是什么？为什么视觉 token 和 prompt 不算 loss？
→ 视频和问题是"给定输入"，模型不需要学"生成视频/生成问题"，梯度只从
   response token 回传，让模型专注学"给定视频和问题时怎么答"。

Q4：+0.5 是不是说明数据没用？
→ 恰恰相反。+0.5 是被 89 道未覆盖题稀释后的全量均值，覆盖子集是 +2.8。
   瓶颈是覆盖率（约 45%）不是数据质量。

Q5：WildClaw 的 +2.3 怎么排除"背答案"？
→ 训练视频与 WildClaw 严格隔离（held-out），训练用的是同类别新视频而非
   评测原题，模型无法靠记忆获益，只能归因于解题路径的真实泛化。

Q6：两轮对照怎么保证归因成立？
→ 唯一变量是模型权重；抽帧数、解码温度、rubric、judge 版本全部锁死。
   任一项漂移，delta 就混入训练无关扰动。

Q7：CoT 是怎么被 SFT 学会的？
→ teacher forcing 下每个推理步 token 都被要求"基于观察+已有推理"预测
   下一步，正确路径整条序列概率被反复抬高；rollout 筛选保证被模仿的
   路径本身是对的。学到的是 p(下一步推理 | 观察, 已有推理) 的行为分布。

Q8：SFT 的边界在哪？
→ 只抬高正样本似然，不显式压低坏样本——不教"好答案好在哪"，那是
   DPO/RL 的工作。所以正样本质量直接决定 SFT 天花板。

Q9：这套流程和你的质检工作有什么关系？
→ 质检标准就是 SFT 正样本的质量定义：准确性拦标签噪声、完整性拦过程
   缺陷、格式拦格式漂移、匹配度拦语言捷径。交付层和消费层是同一套语言。
```

## 十三、闭环逻辑与待深挖方向

三步流程构成一个完整的靶向优化闭环：**轨迹对比**回答"模型错在哪"，**行为引导 Rollout** 回答"高质量正样本该长什么样"，**SFT** 完成参数层面的分布对齐，**评测**做收益归因并指向下一轮靶点。数据侧的四维度质检与算法侧的训练目标在这条链路上是严格对齐的——质检标准就是 SFT 正样本的质量定义。

沿这条链路继续演进，有三个自然方向：

- [ ] **扩覆盖**：优先补齐未覆盖 89 题中模型表现弱的题型，同时补充视频场景多样性；按稀释逻辑推算，全量收益会随覆盖率向子集收益（+2.8）收敛。
- [ ] **为偏好优化备料**：轨迹对比阶段保存的模型错答，天然是 DPO 的 rejected 候选（人工 response 作为 chosen），几乎零额外标注成本就能构造偏好对。
- [ ] **为可验证奖励打基础**：GRPO 依赖能自动判分的奖励，答案规范化（短答案、可抽取、格式统一）能让规则验证器直接打分，这是数据侧标注时可以提前配合的点。
