## 一、项目概览

### 背景

TalkingData 移动广告平台需要识别"点击是否由欺诈产生"（自动点击/机器人点击），目标：预测用户点击后是否完成 APP 安装（是否欺诈点击）。

### 核心数据

```text
├── 数据规模：2 亿条点击数据
├── 正负样本比：1:33（极度不平衡）
├── 特征：IP、App、Device、OS、Channel、点击时间等原始字段
└── 任务：二分类（是否安装 = 是否真实点击）
```

### 你的角色

独立完成全流程：数据处理 → 特征工程 → 模型调优。

### 核心成果

```text
├── 验证集 AUC 0.96
├── 欺诈点击识别召回率 93%
└── IP 分桶 20 个桶分布式处理 2 亿条数据
```

## 二、核心工作内容

### 工作 1：数据处理与特征工程

```text
├── IP 分桶策略：拆分 20 个桶分布式处理（内存/算力约束）
├── 四类高维统计特征：
│   ├── 计数特征：IP 在窗口内的点击次数
│   ├── 去重特征：独立设备/应用数量（同 IP 多设备 = 欺诈信号）
│   ├── 时间间隔特征：点击间隔分布（机器人点击时间均匀）
│   └── 累积计数特征：累计点击趋势
└── 原始字段 → 特征工程：IP、App、Device、OS、Channel、时间
```

### 工作 2：模型调优

```text
├── LightGBM（GBDT 家族，适合高维稀疏 + 大规模）
├── 网格搜索（超参数调优）
├── Early Stopping（防过拟合 + 控制训练时间）
└── 适配极度不平衡场景：
    ├── 样本权重/采样策略
    └── 评价指标选择（AUC 优先，非 Accuracy）
```

## 三、Technical Anatomy

### 主题 1：极度不平衡（1:33）—— 为什么 Accuracy 是陷阱

```text
1:33 不平衡下：
├── 全预测"非欺诈" → Accuracy 97%+，但毫无用处
└── Accuracy 被多数类主导 → 必须换指标

正确指标：
├── AUC（ROC 曲线下面积）：对类别不平衡不敏感，反映排序能力
├── Recall（召回率）：欺诈识别的覆盖率
└── Precision-Recall 曲线：正类极少时更敏感

面试洞察：指标选择由数据分布决定——
"极端不平衡场景必须用 AUC/PR 而非 Accuracy"
这是四视角里算法视角的核心素养
```

### 主题 2：特征工程 —— 欺诈信号藏在"统计规律"里

```text
为什么用统计特征（而非原始字段直接喂）：
├── 原始字段是高基数类别（IP 有数百万取值）→ 直接编码爆炸
├── 欺诈行为的本质是"统计异常"：
│   ├── 同 IP 短时间大量点击（计数特征暴露）
│   ├── 同 IP 大量不同设备（去重特征暴露）
│   ├── 点击间隔均匀分布（时间间隔特征暴露，机器人行为）
│   └── 累计点击的异常增长（累积计数特征暴露）
└── 特征 = 把"领域知识"编码为模型可学习的信号
```

### 主题 3：IP 分桶分布式处理 —— 数据规模的工程约束

```text
2 亿条 × 特征工程 → 单机内存不够
解决方案：IP 分桶
├── 按 IP 哈希分 20 个桶（同 IP 进同桶，保证桶内特征完整）
├── 每桶独立处理（并行/分布式）
└── 合并结果

为什么按 IP 分（而非随机分）：
├── 计数/去重特征需要"同 IP 全量数据"
├── 随机分桶 → 同 IP 散落各桶 → 特征计算不完整
└── 分桶键的选择 = 特征计算正确性的前提

面试价值："分桶策略"体现工程理解——
不是简单并行，而是"分桶键决定特征正确性"
```

### 主题 4：LightGBM —— 为什么选 GBDT

```text
与深度学习对比：
├── 表格数据 + 高基数类别 → GBDT 家族传统最优
├── LightGBM：直方图算法 + 单边梯度采样 → 快且省内存
├── 2 亿条数据能训完（特征工程后维度可控）
└── 可解释性优于深度模型（特征重要性可分析）

超参数（网格搜索）：
├── 学习率 / 树深度 / 叶子数 / 正则化
└── Early Stopping：验证集 loss 不再下降 → 提前停
```

## 五、面试故事

### 版本 A（30 秒）

> 我在 Kaggle 的 TalkingData 广告欺诈检测中，处理 2 亿条点击数据，针对 1:33 极度不平衡问题，设计了 IP 分桶分布式处理 + 四类统计特征（计数/去重/时间间隔/累积计数），用 LightGBM + 网格搜索 + Early Stopping 调优，验证集 AUC 0.96，欺诈召回率 93%。

### 版本 B（2 分钟）

> TalkingData 要求预测用户点击是否由欺诈产生。数据是 2 亿条点击，正负样本 1:33 极度不平衡——全预测"非欺诈"就能有 97% 的 Accuracy，但毫无价值，所以指标我选了 AUC 和召回率。
>
> 特征工程上，我基于欺诈行为的统计规律做了四类特征：计数特征（同 IP 点击次数）、去重特征（同 IP 设备数）、时间间隔特征（机器人点击时间均匀）、累积计数特征。工程上 2 亿条单机处理不了，我按 IP 哈希分 20 个桶分布式处理——分桶键选 IP 而不是随机，因为计数特征需要同 IP 全量数据。
>
> 模型用 LightGBM + 网格搜索 + Early Stopping，最终验证集 AUC 0.96，欺诈识别召回率 93%。

### 版本 C（5 分钟）— 版本 B + 四视角展开

```text
PM 视角：欺诈点击 = 广告主预算损失，模型产出 → 风控拦截
算法视角：不平衡的指标陷阱（Accuracy 误导）；AUC 对分布不敏感；
         统计特征暴露欺诈信号
工程视角：分桶并行（分桶键决定特征正确性）；内存约束；
         可复现性
策略视角：召回 93% 的代价（误杀率权衡）；特征会随欺诈演进失效

反思与局限：
├── 没有做特征重要性的系统分析（为什么某类特征最有效）
├── 阈值选择对 Precision/Recall 的权衡未展开
├── 时间窗口特征没有考虑特征泄漏风险（用未来信息）
└── 若重新做：加入时间序列验证（防泄漏）+ 特征重要性报告
```

## 六、面试官追问准备

**Q1：1:33 不平衡为什么不用过采样/欠采样？**
用了样本权重和指标适配。过采样有风险（重复样本过拟合），欠采样丢信息；LightGBM 自带 sample weight 支持，AUC 指标对不平衡稳健。实际场景还要保留原始分布（线上分布也是 1:33）。

**Q2：AUC 0.96 是不是太高了？有没有过拟合/泄漏风险？**
合理质疑！0.96 有泄漏嫌疑（很多高 AUC 的 Kaggle 方案用未来信息/测试集信息）。诚实回答：训练/验证同分布，但时间序列特征有泄漏风险，重新做会用时间切分验证（前 80% 训练，后 20% 验证）。

**Q3：为什么用 LightGBM 不用 XGBoost？**
两者同族，LightGBM 用直方图算法更快、内存更省，2 亿条场景下训练时间优势明显。XGBoost 精度略高但在该场景差异小。

**Q4：IP 分桶后特征计算怎么合并？**
每桶内完成同 IP 的聚合特征，桶间不交叉（IP 维度独立），最后合并成完整特征矩阵。分桶键保证聚合完整性的前提是同 IP 数据不分裂。

**Q5：欺诈检测的业务落地怎么做？**
模型输出欺诈概率 → 设置阈值 → 高风险点击拦截/二次验证。阈值的业务权衡：拦截太激进误伤真实用户，太松漏掉欺诈——这是策略指标权衡（Recall vs 误杀率）。

**Q6：这个项目对数据类岗位面试的价值是什么？**
它证明了：数据规模处理能力（2 亿条）、特征工程思维（把领域知识编码成特征）、指标选择意识（不平衡场景选对指标）、工程化能力（分布式处理）。这些是数据 Pipeline 岗位的底层能力。

**Q7：四类特征里哪类最重要？**
业务上"时间间隔特征"最能暴露机器人行为（真实用户点击间隔有思考/犹豫，机器人均匀），但量化验证需要特征重要性分析——这是我项目里没做完的，是诚实暴露的局限。

**Q8：如果让你重新做，怎么提升？**
三个方向：① 时间切分验证防泄漏；② 特征重要性分析定位关键信号；③ 欺诈演进的在线检测（特征窗口滚动更新）。

## 九、待深挖方向

### 算法视角待补

- **特征有效性机理**：计数/累积/时间间隔特征为什么能捕捉欺诈模式，缺特征重要性分析和 ablation——AUC 0.96 里哪些特征贡献的说不清
- **时序泄漏风险**：IP 点击序列是时间相关的，当时的验证集划分是否避免了时序泄漏未验证
- **阈值权衡量化**：93% 召回对应的误杀率是多少、业务侧换算成损失/收益没算过

### 工程视角待补

- **分布式处理系统性理解**：IP 分桶是手动实现的"伪分布式"，可连接 Spark/MapReduce 思想补齐分布式处理概念（简历 P2 加分项）
- **Pipeline 可复现性**：网格搜索参数、seed、数据划分没有固定记录，重跑结果不可复现
- **特征失效监控**：特征分布漂移怎么发现、怎么触发重训，没做过（知识树「特征失效」节点仍是 🌱）
