## 二、协作架构与工作流

### 协作架构

```text
数据作业同学 ──标注结果──> 我（质检） ──合格数据──> 算法同学
  ├── 采集                    ├── 质量把关             ├── 数据分析
  ├── 清洗                    ├── 一致性检查           ├── 模型训练
  └── 标注                    └── 与算法对接            └── 评估
```

### 端到端全景流程图（交付层在链路中的位置）

> 一张图看清"我负责的段"在整条数据 → 模型链路里的位置：**左半（采集 → 标注 → 质检 → 三元组）是本文档的交付层，右半（三元组 → SFT → 评测 → delta）是算法侧的消费层**（详见 `vlm-sft-pipeline-review.md`）。我端到端负责的是虚线框内的部分——从寻源采集一直到把合格三元组交出去。

```text
┌──────────────── 交付层（本文档：我端到端负责）────────────────┐
│ 视频采集 / 清洗 / 抽帧                                          │
│     ↓（寻源采集：考点先行，见下一节）                          │
│ 人工标注 prompt + response                                     │
│     ↓                                                          │
│ 四维度质检（准确 / 完整 / 格式 / 匹配）                        │
│     ↓                                                          │
│ 三元组 (video, prompt, response) ── 按周交付 ──┐               │
└────────────────────────────────────────────────┼─────────────┘
                                                  ↓
┌──────────────── 消费层（算法侧：vlm-sft-pipeline-review.md）──┐
│ ① 模型轨迹对比（定位错误靶点，base 基线推理复用为评测第一轮）  │
│ ② 行为引导 Rollout（采样 + 筛选，拒绝采样）                    │
│     ①② + 三元组正样本 → ③ SFT → 两轮对照评测（同 rubric）      │
│     → delta：ClawEval +0.5 / WildClaw +2.3 / 覆盖题 +2.8       │
└────────────────────────────────────────────────────────────────┘
```

**这张图对交付层的意义**：三元组不是终点，而是下游 SFT 的正样本原料。所以交付层的四维度质检（准确 / 完整 / 格式 / 匹配）在消费层各对应一个具体训练风险——两端是同一套语言，详见 `vlm-sft-pipeline-review.md` 第四节。**采集是第一道难度防线（源头对齐示例），质检是最后一道（交付前把关），SFT 是最终消费方。**

### 寻源采集工作流（我负责的环节）

> 核心思路：**先看每道题本质上在考什么，再据此设计检索逻辑寻源，最后用切/拼/合成把难度对齐示例。** 不是"随便找视频"，而是"按考点反向寻源"。

```text
需求：VLM agent 数据质检与重标
    ↓
锁定示例标尺（示例题目定义了目标难度 = 采集的对齐基准）
    ↓
按题型选择 pipeline（判断这道题本质考什么能力 → 走哪条寻源线）
    ↓
┌─────────── 分题型寻源 + 机标（四条并行 pipeline）───────────┐
│ 题型（考点）              寻源 + 机标策略                     │
│ ① 视频细粒度理解    →    事件级寻源 + 机标                    │
│ ② 双语 OCR         →    字幕与画面 OCR 机标                  │
│ ③ 考据检索/文本核查 →    检索与脚本构造机标                   │
│ ④ 工程脚本         →    脚本化构造机标                        │
└──────────────────────────────────────────────────────────┘
    ↓
机标候选：素材 + 题目 + 草稿答案
    ↓
难度是否对齐示例？（对齐基准 = 锁定的示例标尺）
├── 对齐  → 写回作业表，三件套（素材 + query + answer）齐套 → 交付
└── 不对齐 → 换源 / 改题 / 重标 → 回到"机标候选"重新判定（闭环）
```

**四条寻源 pipeline 的对应关系**（题型 → 检索逻辑）：

| 题型（本质考点） | 寻源 + 机标策略 | 检索逻辑要点 |
|------------------|-----------------|--------------|
| 视频细粒度理解 | 事件级寻源 + 机标 | 按"要考的具体事件/动作"精确检索，定位到事件级片段 |
| 双语 OCR | 字幕与画面 OCR 机标 | 找带字幕/画面文字的视频，机标抽取字幕轨与画面文字 |
| 考据检索 / 文本核查 | 检索与脚本构造机标 | 找可核查事实的视频，检索 + 脚本构造标注草稿 |
| 工程脚本 | 脚本化构造机标 | 用脚本化手段构造/生成符合考点的素材与标注 |

**关键设计决策**：

```text
① 考点先行：先判断"这道题本质在考什么能力"，再设计检索逻辑——
   题型决定走哪条寻源 pipeline，避免"找到视频再硬凑题目"。
② 寻源为主，构造为辅：主思路是从 YouTube / B 站等平台寻源；
   个别题目寻源找不到合适素材时，才用切 / 拼 / 合成补齐。
③ 难度对齐是采集的验收关：切/拼/合成的目的不是"造视频"，
   而是把采集到的素材难度做到和示例题目对齐（防难度坍缩的源头治理）。
④ 机标 + 人工闭环：机标产出草稿三件套，难度不对齐则换源/改题/重标，
   直到对齐才写回作业表交付。
```

**寻源采集 ↔ 质检的关系**：寻源阶段的"难度对齐示例"这道验收关，正是难度坍缩（第五节）的**源头治理**——在采集环节就按示例标尺对齐难度，而不是等标注完再靠质检打回。采集是第一道难度防线，质检是最后一道。

### 数据形态（飞书表格作业）

```text
每个 sheet = 一类 topic 题目
├── 首行：示例（素材 + query + answer + 能力维度）
├── 作业区：按示例格式填写视频素材、query、answer、能力维度
└── 任务 1 vs 任务 2 的区别：任务 1 没有 answer 列
    【待确认】任务 1 不写 answer 的用途是什么？
    （可能：纯问题池/评测问题生成/后续统一补答案——问算法确认）
```

### 日常工作流

```text
数据同学完成一批标注
    ↓
我质检：
├── 是否符合标注标准（格式、字段完整性）
├── 是否有重复值
├── 证据是否充分（答案能从素材中推出吗）
├── 难度是否对齐示例（时长、复杂度）← 从翻车案例沉淀的检查项
└── 是否覆盖目标能力维度
    ↓
合格 → 交付算法同学；不合格 → 打回修改/人工修正
    ↓
算法反馈 → 调整质检标准（迭代闭环）
```

### 质检判断标准（关键设计决策）

```text
【已从翻车案例反推，待补充确认】
├── 格式层：字段完整、符合示例格式（飞书表格结构）
├── 唯一性：无重复值
├── 证据层：query 的答案能从素材中推出（不靠常识/外部知识）
├── 难度层：与示例题目的复杂度对齐（噪音量、时长、信息密度）
└── 能力层：题目确实训练目标能力维度（示例要求的能力）
```

## 三、核心认知 1：训练数据三层覆盖框架（已成形 2026-08-19）

> 从执行层反推出的数据设计原理：多样性的本质是能力覆盖。

```text
样本 = 素材（输入）× query（任务）× answer（输出）

素材多样性 → 输入分布覆盖 → 泛化（模型见过多少世界）
├── 视频类型 / 场景分布 / 内容复杂度 / 拍摄条件 / 时长
└── 素材单一 → 过拟合训练分布

query 多样性 → 任务类型覆盖 → 能力清单（模型会做多少事）
├── 感知类 → 物体识别/计数
├── 行为理解类 → 动作识别/过程理解
├── 时序类 → 时间定位/时序推理
├── 因果推理类 → 因果/预测
├── 对比类（多视频）→ 跨视频对齐（L2）
└── 假设迁移类 → 跨场景推理（L3）
    ↔ 与标准文档 L1/L2/L3 维度体系直接对应

answer 多样性 → 输出空间覆盖 → 输出表达
├── 形式：开放描述/选择/判断/数值
├── 确定性：唯一答案 vs 多解合理
├── 依据：单帧可答 vs 跨帧/跨视频证据
└── 证据链 answer = 训练"引用而非编造"
```

**质检视角的应用**（我的角色定位）：三层覆盖框架不只是"出题原理"，更是我的**质检标尺**——

```text
我质检时实际在问：
├── 这条数据的素材，训练的是什么输入分布？（素材对吗/难吗）
├── 这条 query，训练的是哪个能力维度？（任务类型对吗）
└── 这条 answer，训练的是哪种输出形式？（格式/证据对吗）
```

**"站在人的角度看视频/素材"的算法意义**：

```text
人眼 = 当前 VLM 能力的参照系（Ground Truth 校验器）
├── 人工质检 = 用人类视觉认知校验机器标注是否正确
├── 你能注意到的 → 模型需要学会的（能力清单）
├── 你能判断"证据不足" → 模型也会学到错误关联
└── 质检 = 把"正确的人类认知"翻译成"干净的学习信号"
```

## 四、核心认知 2：算法视角的数据交付（已成形 2026-08-19）

> 算法拿到数据，第一反应不是"对不对"，而是"模型会学到什么"。

### 算法的五个检查点

```text
① 信号干净度：错标率、证据不足的题（噪声不是没用，是有害）
② 可学习性：教的是可泛化模式（CoT 框架）还是单个答案；
   格式一致性（多个标注员多种写法 = 混乱信号）；
   难度匹配（太难学不会，太简单无新信息）
③ 分布对齐：能力覆盖矩阵验证 + 配比（长尾能力需更多样本）
④ 可追溯与防泄漏：sample_id 归因；训练/评测数据隔离
⑤ 冗余与重复：与已有数据重复 = 不提供新信号
```

### 交付物检查

```text
视频素材（输入侧）：分布覆盖 + 素材难度（过于简单 = 难度失真）
query（任务侧）：每类量够不够 + 难度梯度合理
answer（输出侧）：格式对齐模型输出头 + 多解标注合理范围 +
   证据可验证（模型答错时区分"数据错"还是"模型错"）
```

### 交付前自查清单（可落地）

```text
□ 这批数据格式合规率？（字段完整、符合示例格式）
□ 重复率？（有没有同素材/同题重复）
□ 每道题的证据充分吗？（答案能从素材里推出吗）
□ 难度对齐示例吗？（时长/复杂度/噪音量）
□ 覆盖了哪些能力维度，各多少条？（覆盖矩阵）
□ 质检时的疑问有没有记录？（问题列表 → 反哺标准文档/反馈算法）
```

## 五、核心认知 3：难度坍缩（Difficulty Collapse）——翻车案例的统一解释

> 从两个翻车案例中提炼的核心认知，面试深度所在。

### 什么是难度坍缩

```text
定义：标注数据的实际难度 < 示例题目定义的目标难度，
     导致模型训练时学到的能力低于预期。

机制：
├── 示例题目 = 难度基准（目标难度）
├── 标注者出题时"顺手简化"（复杂素材 → 简化素材）
├── 数据难度整体偏离目标 → 模型只在简化分布上训练
└── 结果：真实场景复杂度一来，模型就失效
```

### 我的两个翻车案例（第一手证据）

```text
案例 1：空间复杂度坍缩
├── 示例素材：真实复杂地铁线路图（多线路、噪音信息多）
├── 实际出题：只给交叉线路的极简示意图
├── 后果：模型只能识别"交叉线路"，不能识别噪音线路
└── 本质：噪音量（干扰信息）是难度的一部分，被悄悄删掉了

案例 2：时间维度坍缩
├── 示例素材：1 小时长视频
├── 实际出题：只给 10s 短视频
├── 后果：模型训练缺失长视频难度（信息密度、跨时段关联）
└── 本质：时长 = 难度维度，标注时被压缩（后已补充修正）
```

### 算法视角的解释（为什么这是有害的）

```text
训练数据难度 = 模型能力天花板的一部分：
├── 数据难度低 → 模型在该能力上的上限低
├── 目标难度 1h 长视频的"跨时间信息整合"能力
│   → 10s 视频根本给不出这个学习信号
└── 数据看起来"都对"，但信号强度不够 → 静默的质量损失
    （比错标更隐蔽：错标能被发现，难度坍缩不易被发现）
```

### 面试表达

```text
"我在质检中发现两类典型的难度坍缩：空间维度上，示例是复杂
地铁图，标注员只给极简交叉图，噪音信息被删掉，模型只能学
到简单模式识别；时间维度上，示例是 1 小时视频，实际只给了
10 秒片段，长视频的跨时段信息整合能力根本没有训练信号。
我发现数据'都对'但难度系统性偏离目标——我把这定义为
难度坍缩，并把它加进了质检标准：复杂度对齐、时长对齐。"
```

## 六、核心认知 4：长尾分布与训练策略（算法反馈解读）

> 算法原话："示例题目为 1h，训练使用 1h 的视频长度是否可以接受，会不会太长尾了。考虑被 drop 覆盖一下分布，不行就放在 sft 尝试解决。"
> 这句话没看懂——逐句解读：

### 拆解解读

```text
① "太长尾了" → 长尾分布（Long-tail Distribution）
├── 训练数据时长分布：绝大多数样本是 10s~5min，1h 是极少数
├── 长尾问题：样本极少 → 学不到稳定特征；训练成本高（序列长）
└── 分布失衡 → 模型倾向"学会大多数"，忽略长尾

② "被 drop 覆盖一下分布" → 分布控制的采样策略
├── drop = 训练管线里按概率丢弃/降采样过长样本
├── 目的：控制参与训练的长度分布（避免 1h 样本扭曲计算成本）
└── 覆盖分布 = 保证训练集中各长度段都有代表性样本

③ "不行就放在 sft 尝试解决" → 训练阶段的分工
├── 通用阶段（预训练/继续预训练）：分布均衡优先，长尾数据
│   成本高、收益不稳
├── SFT 阶段：数据量小、可精挑 → 专门强化特定能力
│   （如长视频理解）的"兜底方案"
└── 本质：不是所有数据都等权重，数据要匹配训练策略
```

### 对质检工作的启示

```text
算法视角下"好数据"的定义：
├── 不是"每条都对"，而是"分布可控 + 难度对齐 + 无噪声"
├── 我交付的 1h 长视频数据 → 算法可能降采样/drop/转 SFT
```

### A1 数据合格的三层标准（Q6 算法版）

```text
算法判断数据合格，不看"对不对"，看三层：

L1 Correctness（对不对）——及格线
├── 答案正确、无歧义（唯一解或合理范围明确）
├── SFT 数据错标率目标 < 1%（错标 = 错误梯度）
└── 自问：模型学完这一条，行为会变好吗？

L2 Usefulness（有没有用）——信号强度
├── 难度匹配模型当前能力曲线
│   ├── 太简单：模型已收敛，无新梯度（浪费训练步）
│   └── 太难：学不动，loss 被拉高，数据噪声化
├── 是否提供新信息（新场景/新能力/新难度组合）
└── 格式对齐管线（token 预算、字段、长度分布）

L3 Compatibility（配不配）——分布适配
├── 与当前训练阶段匹配（预训练要均衡，SFT 要精挑）
├── 与已有数据不重复（重复 = 过拟合该分布）
└── 能力配比符合 Data Recipe

一句话：数据"对"只是及格，"有用"是目标，
"配得上训练策略"才是合格交付。
```

### A2 能力维度统计的意义（Q9 算法版）

```text
Data Recipe（数据配方）是算法主动设计的：
├── 模型某能力弱（如长视频检索）→ 该维度加量
├── 某维度过量 → 压制其他能力（能力失衡）
├── 评测归因：能力涨跌 → 归因到数据配比变化
└── 74 topic × 5 条的意义 = 验证配方方向，
    不是追求数量（"前期验证阶段"的算法解释）

可落地的统计方法：
├── 按能力维度 pivot：维度 × 数量 × 难度（时长/复杂度）
├── Excel 即可，产出"能力覆盖矩阵"
└── 交付时附矩阵 = 从"交数据"变成"交配方视图"
```

### A3 好的出题长什么样（Q5 算法版）

```text
query 设计五原则：
① 任务边界清晰：一道题只考一个能力（信号不混杂）
② 难度锚定示例：示例怎么难，数据就怎么难（防难度坍缩）
③ 答案可验证：Ground Truth 必须能从素材唯一推出
   （否则训练信号有歧义，评测无法判对错）
④ 信息密度匹配：长视频题必须真正用到跨时段信息
   （否则"长视频"只是形式，没训练到长视频能力）
⑤ 反捷径：防止模型用标题/水印/文本线索猜答案（打码目的）

好题 vs 坏题：
├── 坏题："视频里发生了什么？"（开放到无法判定）
├── 好题："视频 3 分钟处的蓝色物体，和结尾处物体是什么
│   关系？"（锚定具体证据，答案可验证）
└── "长视频找特定物品/事件"是标准好题形态
```

### A4 任务 1 无 answer 列的算法解读

```text
最可能的解读（按可能性排序）：
① 问题池先行（最可能）
   ├── 先低成本产问题 → 验证问题质量与分布
   └── 确认后再花高成本写答案（答案标注是数据生产
       里最贵的环节：人工看素材 + 推理 + 校验）
   本质：阶段化生产，降低风险——问题质量不行就不浪费答案成本
② 评测问题池：题目用于评测，答案判定时统一给出
③ 自生成答案管线：问题喂给模型生成答案，人工校验
④ 预训练格式样本：只学任务指令形态，不需要答案

"数据管线的阶段化成本控制"这个故事
```

### A5 质检 rubric 的算法版设计（Q12 延伸）

```text
Rubric 核心：每一层标注"自动化程度"

L1 结构层（规则代码化，100% 自动）
├── 字段完整、query 是问句、answer 类型匹配 query
└── 素材链接去重 + query 去重

L2 证据层（VLM/LLM-as-judge，批量）
├── 素材抽帧 → 判断 answer 能否从素材验证
├── 歧义检测：query 是否唯一解
└── 难点：素材类型多（视频抽帧+时间定位成本高）→ 抽样

L3 难度层（规则 + 抽样人工）
├── 可量化：时长/分辨率/帧数/打码占比 vs 示例分布
└── 不可量化（语义复杂度）→ 人工对比示例

L4 能力层（规则 + LLM 分类）
├── 能力维度列校验（规则）
├── query 类型 → 维度映射（LLM 分类 + 人工抽检）
└── 输出：覆盖矩阵统计

闭环（与 CoT 5 层 Gate 同构）：
├── 每层 pass/fail + 原因 → 失败分布
├── 失败分布 → 反馈数据同学 + 规则迭代
└── 人工抽检 10% 校准自动化层（一致率）
```

### A6 难度坍缩的自动化检测

```text
三层次检测（复用三层 Grader 思维）：
① 规则层（全量，零成本）
   ├── 时长分布 vs 示例：1h 示例 vs 10s 数据 → 直接检出
   ├── 复杂度代理：分辨率、帧数、素材大小
   └── 噪音代理：打码面积、文本密度
② VLM/LLM 层（抽样/全量）：难度对齐打分
   └── 提示："示例难度 vs 该数据难度，是否对齐？"
③ 人工层（抽检）：校准 LLM 层阈值
```

### A7 评测判分 vs 训练数据校验（2026-08-19 新增）

> 背景：研发给了逐题评分代码，用户确认是**评测集判分用**，质检侧还没用上。
> 核心区分：评测判分 ≠ 训练数据校验，两套完全不同的代码逻辑。

```text
评测判分（研发评分代码）：
├── 对象：模型输出（模型怎么答题）
├── 目标：判断"模型答得对不对"
├── 特性：输出开放 → 代码负责判定
└── 形态：判定逻辑（匹配/比较/规则）

训练数据校验（质检代码）：
├── 对象：标注样本（素材+query+answer）
├── 目标：判断"这条数据能不能进训练集"
├── 特性：多维度质量检查，不止"答案对不对"
└── 形态：分层校验组合
```

**训练数据校验四层体系**：

```text
L1 结构校验（纯规则代码，全量自动，零模型成本）
├── 字段完整（素材链接非空可访问/query/answer 非空）
├── 格式校验（query 是问句、answer 类型匹配 query）
├── 枚举校验（能力维度 ∈ 合法集合）
└── 去重（素材+query 组合）

L2 统计校验（批次级，全量自动）
├── 能力维度覆盖矩阵（每维度数量/难度分布）
├── 时长分布 vs 示例分布（难度对齐 → 检出难度坍缩）
└── 题型多样性

L3 语义校验（VLM/LLM-as-judge，批量）
├── answer 正确性（能从素材验证：抽帧/解析/运行）
├── 证据充分性（答案确实在素材里）
├── 歧义检测（唯一解）
└── 难度对齐（vs 示例打分）

L4 人工抽检（抽样 10%，校准 L3 阈值）
```

**Agent 化质检的正确架构**（Q12 方案校准）：

```text
Agent 用武之地：多素材类型的语义校验（L3）
├── 视频 → 抽帧 + 时间定位（工具调用）
├── 文档 → 解析
├── 代码 → 运行验证
└── 图片 → 视觉理解

Agent 边界：
├── L1/L2 不需要 agent（规则代码更便宜可靠）
├── 全量 LLM 校验成本高（400 条可行，规模化贵）
└── 正确架构：规则层全量过滤 → LLM 层处理语义 →
    人工层校准
```

**评分代码的正确用法**（质检借力）：

```text
评分代码 = "什么算对"的官方定义：
├── 训练数据 answer 按"评分代码能判对"的形态写
│   → 转评测集时无缝（连接 Evals 落地 2）
├── 问研发："答案怎么写评分代码能稳定判对？"
│   = 格式规范的官方答案
└── 质检目标：让"标注答案"和"评测判定"标准一致

"评分代码对答案格式没有预期"的解读：
├── 评测判分不需要格式预期（模型输出开放，靠判定逻辑）
├── 但训练校验恰恰需要格式控制（信号一致性）
└── 格式规范要质检侧自己建——这是质检规则的价值
```

**明天问研发的三个问题**：

```text
① "评分代码是评测用的，训练数据校验你们用什么？
   还是由我们质检侧建？"（边界确认）
② "答案按什么形态写，评分代码能稳定判对？"
   （格式规范官方标准）
③ "训练数据质检的标准你们有吗？还是只有示例？"
   （rubric 原料）
```

### A8 研发评分框架 vs 质检 rubric 差距对照（2026-08-20 新增）

> 输入：`notebook/vlm任务2评分标准rubric整理分析.md`（39-sheet 判分规范解剖）
> 对照对象：A5 质检 rubric 算法版四层设计（结构/证据/难度/能力）

**第一步：抽象研发评分框架**

```text
结构（5 部件）：
├── 任务对象：识别什么（哪句字幕 / 哪个比分 / 哪个 segment）
├── 证据边界：证据只能来自哪（时间窗 / 字幕轨 / 画面对象 / 段落）
├── 输出格式：顺序 / 去重 / 一行一个 / 只输出整数 / 起止时间
├── 容错规则：accepted forms / 大小写标点忽略 / 相似度阈值 /
│   数值容差 / 时间容差 / 部分分权重
└── 排除项：distractor 数字 / 跨 topic 字幕 / 错误单位 / 倒序比分

判分形态：
├── Deterministic 0/1（单一事实题：比分 / 计数 / 速度 → 全规则判分）
├── 相似度阈值（开放输出：字幕匹配 → mean best-position similarity）
├── 三类容差（文本 ≥ 0.9 / 数值 ± 0.5 / 时间 ± 3s）
└── 部分分权重（子问题加权：0.6/0.4、0.4/0.3/0.3）

生产方式：规范与 judge 代码模板一体（[RUBRIC] / [extra_rubric] /
def grade(**kwargs)），per-sheet 一个判分器
```

**第二步：双向差距对照**

```text
质检有、研发没有的（定位差异，非缺陷）：
├── 难度层（L3）：研发只判"对不对"，不看难度；训练数据必须
│   难度对齐（难度坍缩）→ 印证 A7：两套系统定位不同
├── 能力维度 + 覆盖矩阵（L4）：研发按 sheet 判分，不统计覆盖
└── 失败分布闭环：A5 有"pass/fail + 失败分布 → 规则迭代 +
    10% 人工校准"，研发评分标准未见显式闭环机制

研发有、质检缺的（质检可直接借鉴 ⭐）：
├── ① 容错规则缺失：A5 结构层只查"字段完整 / 类型匹配"，
│   没有"什么算对"的容错定义（accepted forms / 阈值 / 部分分）
│   → 质检标准补"答案判定规则"：把对 / 部分对 / 错写死
├── ② 排除项缺失：没有"像答案但不能算"的硬负例（distractor、
│   跨段素材、错误单位）；歧义检测只在 L2 一句"唯一解"
│   → 质检补"证据排除项"：答案在素材里但来自错误位置
├── ③ 证据边界不精确：A5 只问"能否验证"，不问"证据来源
│   是否唯一 / 限定"；研发把证据来源写死（时间窗 / 字幕轨 /
│   画面对象）→ 质检证据层升级为"证据来源约束 + 唯一性检查"
├── ④ 确定性优先原则：研发单一事实题全规则化 0/1；
│   A5 把"答案对不对"默认交给 LLM，结构层只做字段检查
│   → 质检结构层可扩展：格式容错 / 枚举匹配先规则化
└── ⑤ 答案格式官方标准：研发 accepted forms = "答案怎么写
    评分代码能稳定判对"的官方答案（对应问题②）
    → 质检格式校验直接对齐，训练 → 评测无缝（连接 Evals 落地 2）

结论：质检 rubric 与研发评分的差距 = 面试深度：
├── 质检四层 = "数据能不能进训练集"（结构 / 证据 / 难度 / 能力）
├── 研发评分 = "模型答得对不对"（对象 / 边界 / 格式 / 容错 / 排除）
├── 交叉点 = 格式规范与容错规则：标注答案按"评分代码可判对"
│   的形式写 = 训练数据校验与评测判分的握手协议
└── 落地：质检 rubric 四层 → 五层（结构 / 证据 / 难度 / 能力 / 容错）
    或把容错与排除项并入结构层 + 证据层
```

**对四个问题的更新**：

```text
① 评分代码用途 → 已确认：评测集判分用，质检侧未用上（A7）
② 答案格式官方标准 → 已部分回答：accepted forms + 容差规则
   就是官方形态规范；仍需向研发确认训练数据是否直接复用
③ 训练数据校验标准 → 研发评分不覆盖难度 / 覆盖 / 闭环，
   训练校验标准大概率由质检侧自建（A5 方案成立）
```
