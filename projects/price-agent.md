## 一、项目概览

### 背景痛点

```text
① 多平台搜索低效：比价要在多个电商平台反复搜索
② 模糊需求难召回："哪个手机打游戏好"这类问题传统搜索召回差
③ 比价不可信：商品规格混乱，别名/参数不统一，比价不可靠
```

### 产品定位

面向搜索场景的 AI 比价助手：识别用户意图（比价/对比/推荐/混合），路由到最优执行路径，支持多商品对比、语义推荐、图片识物转比价。

### 你的角色

独立完成产品架构设计 + 评测体系设计 + 关键迭代决策（个人自驱项目）。

### 核心数据

```text
├── 7 阶段分层评测方案，158+ 个测试用例
├── 17 字段商品数据模型（手机品类）
├── 7 类使用场景标签
├── 6 个 Agent 工具
└── 语义权重参数 α=0.7、追问上限 3 次（评测驱动的关键决策）
```

## 三、Technical Anatomy

### 主题 1：意图路由 —— 为什么"意图可分"是前提

```text
将"用户意图多样"拆解为四类：
├── 查价 / 对比 / 推荐 / 引导购物

为什么能路由：
├── 四类意图的执行路径差异显著（查价=一次检索；对比=多步骤）
├── 意图边界清晰（用户 query 的句式/语义特征可区分）
└── 路由正确 → 每类意图走最优路径

路由失败的代价：
├── 意图误判 → 执行路径错误 → 结果完全跑偏
└── 所以意图分类准确率是系统第一指标

与百度/第四范式连接：路由架构（意图分流）是跨项目反复出现的模式
```

### 主题 2：7 阶段分层评测 —— 评测体系的分层逻辑

```text
为什么分层（vs 一把测）：
├── 分层定位问题：P0 单元挂 → 问题在处理器解析
│   P2 端到端挂 → 可能是任何环节
├── 分层隔离故障域：每层失败对应明确的修复方向
└── 分层控制成本：单元层快速跑，端到端层慢跑

层级设计逻辑：
├── 自底向上：单元 → 属性解析 → 端到端 → 能力边界
├── 自内向外：功能验证（P0-P2）→ 能力探索（P3）→ 基准汇总（P4）
├── 迭代验证（P5）→ 新能力扩展（P6）
└── 行业专项（IT3C）与通用评测分离

面试价值：这套分层和"单元测试 → 集成测试 → E2E 测试"同构，
证明你理解评测的工程化
```

### 主题 3：归一化 —— 数据质量的前置环节

```text
问题：同一处理器多种叫法（骁龙8 Gen3 / 骁龙8Gen3 / SD 8 Gen 3）
├── 归一化别名体系：多别名 → 标准实体
├── 覆盖处理器、品牌、规格等关键实体
└── 评测发现长尾瓶颈 → 引入语义向量召回作为升级路径
    + 功能开关支持无缝降级

为什么是数据问题：
├── 不归一化 → 比价错误（同物不同名被当成两个商品）
├── 归一化 = 数据清洗（实体对齐）在商品场景的落地
└── 与字节学科标签纠错的同构：两步漏斗（规则 → LLM → 仲裁）
```

### 主题 4：自反思纠错 —— 幻觉缓解的工程手段

```text
问题：工具返回空结果时，LLM 倾向编造答案（幻觉）
设计：
├── 检测：工具结果为空 / 置信度低 → 触发反思
├── 反思：注入提示（"检索无结果，尝试改写关键词/换工具"）
├── 重试：最多 N 次
└── 兜底：N 次后仍失败 → 明确告知用户，不编造

本质：把"模型幻觉"转化为"可检测可恢复的流程问题"
面试价值：这是 Agent 可靠性设计的经典 case
```

## 六、面试官追问准备

**Q1：为什么用三模式混合而不是单一模式？**
不同意图的最优执行路径不同：推荐型需要语义工具，多商品对比需要多步骤规划（Plan-Execute），简单查价直接检索（ReAct）。单一模式要么慢要么不准。

**Q2：意图分类怎么做的？准确率多少？**
规则 + LLM 分类（Few-Shot 约束），四类意图边界清晰。局限：没有留存量化的准确率，这是我要补的指标。面试可讲"准确率是路由架构的系统瓶颈"这一认知。

**Q3：α=0.7 怎么来的？**
评测驱动的：语义 vs 关键词召回在测试集上的对比，α 调高模糊 query 召回好但精确编号差，α 调低反之；0.7 是测试集上的平衡点。

**Q4：17 字段数据模型怎么设计的？**
从"比价需要哪些属性"反推：核心规格（处理器/内存/存储）、价格（当前/历史）、渠道（平台/店铺）、评价维度等。字段设计决定下游评分和对比的可用性。

**Q5：归一化别名体系怎么维护？**
规则词典起步，评测发现长尾瓶颈（新别名覆盖不全）→ 引入语义向量召回作为升级路径，功能开关无缝降级——用数据决定升级时机。

**Q6：追问上限为什么是 3 次？**
需求收敛和体验损耗的平衡。追问过多用户流失，过少需求不明确。3 次来自评测 + 主观体验的判断，是典型的体验 vs 效果的权衡决策。

**Q7：自反思纠错会不会引入新问题？**
重试可能陷入死循环 → 设最大重试次数，N 次后明确告知用户失败。反思注入改变 prompt 也可能导致输出漂移 → 反思模板固定化。

**Q8：评测体系最大的收获是什么？**
评测驱动决策的意识——每一次策略调整都有评测结论支撑，而不是拍脑袋。这直接延续到了我在字节的质检规则设计和 Eval Set 建设。

**Q9：和市面上的比价产品比，你的差异是什么？**
AI 意图理解（模糊需求）vs 传统比价（精确输入）；多模态（图片识物转比价）；分层评测保证能力边界可量化。

**Q10：这个项目你最有成就感的一个决策？**
处理器归一化从规则升级到语义召回——评测发现规则词典的长尾瓶颈，用数据说服自己放弃"补规则"走向"换方案"。
