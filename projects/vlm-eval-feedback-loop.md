# VLM 评测反馈闭环（工作工具）

> 目的：把"交付即结束"升级为 **评测 → 归因 → 策略反馈 → 迭代验证** 闭环
> 定位支撑：LLM 数据与评测工程师的"算法反馈并迭代"环节（gap-analysis 第二章主线三）
> 使用节奏：每轮交付后 1-2 天完成归因，周内发出策略反馈

---

## 一、四类根因分类框架

```text
bad case 从哪来（归因第一步：分类，不要个案分析）：
│
├── 1. 任务定义问题（标准文档有歧义 / 任务本身难界定）
│   ├── 判定线索：同一 prompt 多人判分结果分散、标准文档解释不清、
│   │             某能力维度整体失败率异常
│   ├── 归因动作：回到标准文档，查 5 部件（任务对象/证据边界/输出格式/
│   │             容错规则/排除项）哪部分模糊
│   └── 策略方向：修订标准 / 补充示例 / prompt 模板调整
│
├── 2. 数据源问题（素材不足 / 质量差）
│   ├── 判定线索：某能力维度成批失败、可配对视频稀缺、
│   │             素材分辨率/时长/信息密度不达标
│   ├── 归因动作：查采集关键词覆盖度矩阵、可配对率统计
│   └── 策略方向：补关键词 / 换数据源 / 调整配比
│
├── 3. 标注执行问题（人员理解偏差 / 漏标 / 错标）
│   ├── 判定线索：个案失败、同类问题集中在少数标注者、格式错误
│   ├── 归因动作：对照标注指引，定位示例/培训缺口
│   └── 策略方向：补标注指引示例 / 定向培训 / 质检前置
│
└── 4. 评测规范问题（容差设计不合理 / 判分规则误伤）
    ├── 判定线索：某类答案系统性判错、容差边界附近大量失败
    ├── 归因动作：检查判分五模式（规则/容差/部分分/相似度/LLM fallback）
    │             哪一层在误伤
    └── 策略方向：调整容差 / 修正判分代码 / 增加排除项
```

## 二、归因报告模板（每轮交付后填）

```text
# VLM 数据生产 第 X 轮 归因报告

## 本轮概况
- 交付条数：N ｜ 合格率：X% ｜ 失败条数：M
- 失败分布（四类根因占比）：
  ├── 任务定义：X%（N 条）
  ├── 数据源：X%（N 条）
  ├── 标注执行：X%（N 条）
  └── 评测规范：X%（N 条）

## bad case 明细（重点条目）
| 样本 ID | 能力维度 | 判分结果 | 根因分类 | 证据/复现 | 严重度 |
|---------|---------|---------|---------|-----------|--------|
|         |         |         |         |           | 高/中/低 |

## 根因结论
（每类根因一句话结论：是什么、为什么、影响多大）
```

## 三、数据策略反馈报告（给算法/研发，一页纸）

```text
# VLM 数据生产 第 X 轮 策略反馈

## 本轮概况
交付 N 条，合格率 X%（较上轮 ±X pp），失败主要分布在：……

## 根因与建议（按影响排序，最多 3 条）
├── 根因 A（任务定义，占失败 40%）
│   ├── 现象：L2 时间交叉引用类 prompt 集体判错
│   ├── 建议：修订标准文档证据边界表述 + 补 3 个正反示例
│   └── 预期影响：该类失败预计减半，L2 覆盖率缺口收窄
├── 根因 B（数据源，占失败 25%）
│   └── 建议：采集关键词补"同实体不同状态"方向 10 个
└── 根因 C（标注执行，占失败 15%）
    └── 建议：质检前置到出题环节 + 示例库扩充

## 下轮计划
- 只调 1 个主变量：______（一次一个，保证可归因）
- 其余变量保持不动

## 需要算法侧配合
- 复测结果回传：这批数据纳入后，模型在 XX 评测上的表现
- 关注点：哪些 bad case 被修复 / 哪些仍在
```

## 四、闭环验证记录表（策略前 vs 策略后）

```text
# 策略验证记录（长期维护，面试核心证据）

| 轮次 | 数据策略调整 | 预期影响 | 实际结果（合格率/维度占比/bad case 修复） | 验证结论 |
|------|-------------|---------|-------------------------------------------|---------|
| 第X轮 | 基线 | - | - | - |
| 第X+1轮 | 调了什么 | 预计 X | 实测 X | 有效/无效+原因 |

验证原则：
├── 单变量：一轮只改一个主变量
├── 同评测集：新旧对比用同一套判分规范，不跨版本比分数
└── 区分"数据问题 vs 评测问题"：先查评测规范误伤，再归因数据
```

## 使用检查清单

```text
每轮交付后：
[ ] 判分结果按四类根因完成分类（量化占比）
[ ] bad case 明细表填完（至少 5 条重点）
[ ] 一页纸策略反馈发给算法/研发
[ ] 下轮主变量已定（只调一个）
[ ] 策略验证记录表追加一行
```

> 完成一轮闭环 = 可讲述故事："我做了 X 归因 → 提了 Y 建议 → 下轮验证 Z 有效/无效"
> 追问三层不塌：每一条都来自真实记录。
