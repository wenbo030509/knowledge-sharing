## 一、数据如何进入训练（你已有 70%，补流图）

### SFT：teacher forcing

```text
数据（输入 prompt + 期望输出 CoT/response）
→ batch（打散 + 配比混合）
→ tokenizer（转 token id）
→ 模型前向（teacher forcing：期望输出作为每一步的输入，逐 token 计算 loss）
→ 交叉熵 loss（每个 token 的预测概率 vs 标准答案）
→ 梯度反传 → 参数更新

关键：SFT 的 loss 全部来自标注数据
├── 错标 = 直接污染 loss（模型在学错误输出）
└── 所以质检（格式/内容/标签）不是流程要求，是 loss 质量的护栏
```

### RL：reward 信号

```text
SFT 教"说什么"，RL 教"怎么做得更好"
数据（prompt）→ 模型自由生成 → reward 打分 → 策略梯度更新

关键连接（Reward Model 解剖）：
├── reward function = 评测标准可执行化
├── 规则 reward（RLVR，如 DeepSeek-R1）与确定性判分同构
└── 你设计的判分规范（5 部件 + 判分五模式）就是 reward 的候选形态
    → 评测设计做得好的人，天然理解 RL 数据需求
```

### 你需要能画的图

```text
数据 → batch → loss → 梯度
     ↑                ↓
   配比/质量       参数更新
     ↑
  评测结果反馈（你在这里发力）
```

## 二、评测结果如何反馈算法（你已有 60%，补映射）

### bad case 类型 → 数据策略 映射表

| 评测发现（bad case 类型） | 数据策略动作 | 预期影响 |
|--------------------------|-------------|---------|
| 某能力维度失败率高（任务定义问题） | 修订标准文档 / prompt 模板 / 补示例 | 该维度样本可学性提升 |
| 某维度样本稀缺（数据源问题） | 补关键词 / 调整采集配比 | 覆盖度上升，能力涨跌再分布 |
| 标注质量差（执行问题） | 质检前置 / 培训 / 规则收紧 | 信噪比提升 |
| 判分误伤（评测规范问题） | 调容差 / 修判分代码 | 分数失真消除（先查这个！） |

### 配比 → 能力涨跌（已有实践）

```text
数量 → 覆盖度（能力面）
质量 → 信噪比（单条可学性）
单条数据权重微乎其微，但配比决定能力涨跌（黑盒 20% 配比实践）
```

### 关键认知：评测结果是训练决策的输入

```text
算法团队拿到评测/bad case 分布后做的决策：
├── 调整数据配比（哪类数据加量）
├── 调整 reward 设计（哪类行为要奖励）
├── 调整 prompt 模板（任务定义问题）
└── 决定下一轮采什么数据（数据飞轮的起点）
→ 你的归因报告质量 = 算法决策质量的地基
```

## 三、验证方法（最缺，重点补）

### 核心：同评测集新旧对比

```text
原理：控制变量——评测集不变，看数据策略调整前后模型/数据表现

做法：
├── 策略前：本轮评测结果（基线）
├── 调整：只改 1 个主变量（单变量原则）
└── 策略后：下一轮用同一套判分规范复测

对比什么：
├── 合格率 / 失败率
├── 各能力维度占比分布
├── 特定 bad case 修复情况（是否还有同类失败）
```

### 单变量原则（为什么一次只改一个）

```text
改了 3 个变量，指标涨了——
├── 你无法归因是哪个变量起作用
├── 归因失败 = 迭代无效 = 闭环断裂
└── 一次一个变量，涨了归因明确，跌了回滚明确
```

### 护栏指标（防"指标涨但实际变差"）

```text
主指标涨了，要同时看护栏：
├── 合格率涨了，但难度分布坍缩？（难度坍缩：全变简单样本）
├── 覆盖率涨了，但信噪比掉了？（为凑数收垃圾素材）
└── 这是策略视角的核心追问：有没有指标涨了但实际效果没变
```

### 统计显著性问题（连接评测方法论主线）

```text
样本量小时，合格率 ±5pp 可能是噪声
├── 评测集统计学的缺口就在这（gap-analysis 主线一）
└── 先记"样本量 + 对比结果"，显著性学习后再回来校准
```

## 四、算法接口语言（谈判筹码）

### 算法关心什么

```text
├── loss 曲线（训练是否正常）
├── 评测指标涨跌（能力是否提升）
├── bad case 修复率（问题是否解决）
└── 数据配比与质量（信噪比、覆盖度、难度分布）
```

### 汇报公式

```text
弱："合格率 79%"（数据侧语言）
强："我把评测结果做了四类根因归因，任务定义问题占 40%，
    建议修订证据边界表述——预计该维度失败减半。
    下轮只调这一个变量，复测用同一套判分规范。
    需要算法侧回传这批数据在 XX 评测上的表现。"

拆解：
├── 归因：四类根因（分类而非个案）
├── 建议：根因 → 动作 → 预期影响
├── 验证：单变量 + 同评测集
└── 协作：给算法明确的最小配合请求
```

## 五、与知识树的连接

- `评测结果反馈` ← → `数据飞轮`：评测 → bad case → 数据策略 → 训练迭代
- `判分规范` ← → `reward 设计`：判分五模式 = 规则 reward 的评测侧实现
- `质检` ← → `SFT loss 护栏`：错标直接污染 teacher forcing loss
- `单变量验证` ← → `实验设计`：策略 PM 核心技能的本地化实践
- `护栏指标` ← → `难度坍缩`：合格率涨 ≠ 数据变好，要看难度分布
- `数据配比` ← → `能力涨跌`：数量→覆盖度，质量→信噪比

## 六、讲述故事

### 30 秒版本

> "我在字节把评测从交付报告升级为策略反馈：把判分结果按四类根因归因（任务定义/数据源/标注执行/评测规范），给算法提数据策略建议——每类根因对应一条动作和预期影响。下轮只调一个变量，用同一套判分规范复测验证，形成'归因 → 建议 → 验证'的闭环。"

### 2 分钟展开（四视角）

```text
PM 视角：评测结果 = 数据策略决策的输入，我的报告质量决定算法决策质量
算法视角：reward = 评测标准可执行化（判分规范 → RL 数据需求）；SFT loss 质量靠质检护栏
工程视角：闭环要可记录——归因模板 + 验证记录表（策略前 vs 后）
策略视角：单变量原则 + 护栏指标（防"指标涨但实际没变"）+ 同评测集对比
```
