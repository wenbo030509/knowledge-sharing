# 搜索工程 → Agent 构建与评测的迁移地图

> 定位：从 **Agent 构建与评测** 视角学习工业项目（搜索/推荐等）的"取长补短"方法论。
> 思路：每精读一个工业项目，先诚实盘点它覆盖了什么（微调/后训练/harness/agent/评测），再提取可迁移范式，最后落到可执行动作。
> 首个案例：美团搜索 3.0 LLM 语义表征（papers/07）
> 日期：2026-08-21 / 状态：🌿 持续生长

---

## 一、盘点框架（对任何工业项目都适用）

```text
问五个问题：
├── 它提了微调吗？（模型怎么适配任务：全参 / LoRA / 训练目标设计）
├── 它提了后训练吗？（SFT / RL / 数据配方——搜索常叫"训练目标"）
├── 它提了 harness 吗？（模型能力怎么接入系统：接口/门控/加载方式）
├── 它提了 agent 吗？（多步决策 / 工具使用 / 生成式交互）
└── 它提了评测吗？（离线指标 / 在线实验 / 归因方法）
```

## 二、美团搜索 3.0 的盘点结论

| 概念 | 覆盖状态 | 证据（原文） |
|------|---------|------------|
| 微调 | ✅ 技术主线 | 全参数微调（一期）→ LoRA r=8/α=32 q_proj+v_proj（二期）；基座 0.5B~8B 横向对比；"针对下挂场景重训"展望 |
| 后训练 | ⚠️ 间接 | LoRA = post-training 的 PEFT 形式；对比学习配方 + 五元组数据构造 = post-training 核心动作，但文章不用该词 |
| harness | ❌ 未提（可延伸） | "表征注入方式"演进（拼接→分桶→双融合→PEPNet 门控）= harness 接口设计的搜索版 |
| agent | ❌ 未提（可延伸） | 展望中 SID 生成式检索、Producer→Consumer 闭环是检索×生成交叉 |
| 评测 | ✅ 隐藏主线 | 离线（Q2I-AUC/NDCG/消融/Droprank）+ 在线（AB/AA/漏斗/LR/TP90） |

**核心判断：** 这是"微调 + 评测"双主线文章。评测层是对 Agent 构建最大的可迁移资产，harness/agent 是需要借力延伸的部分。

## 三、六个可迁移范式（Agent 视角取长补短）

### 范式 ① 双层评测体系（离线 + 在线）

```text
搜索做法：离线（AUC/NDCG/消融）筛方案 → 在线（AB/AA 校验）验真
         三期都是"离线验证 → 小流量线上 → AA 通过 → 放量"
Agent 现状：离线基准（SWE-bench 类）成熟，在线层基本空白
可执行：Agent 上线必须有"小流量真实用户 AB"阶段；
        离线指标涨 ≠ 真实场景好用
```

### 范式 ② 指标归因（过程指标 vs 结果指标）

```text
搜索案例：QV -0.05%（不显著）但 QV_CTR +0.10pp（显著）
归因结论：减少无效曝光 = 曝光质量优化，不是流量损失
         （下钻到事业部：QV -0.70% 但 QV_CTR +0.24pp，方向一致）
Agent 对应：工具调用次数降但任务完成率升 = 效率提升不是能力退化
可执行：Agent 评测同时看过程+结果指标，单看一个会误判；
        指标异常先下钻分层（按场景/用户群），再下结论
```

### 范式 ③ 难负样本 = 从真实行为挖训练信号

```text
搜索做法："同请求同商家曝光未点击"——用户真实决策边界
         消融：Order-AUC +11.02pp > Click-AUC +4.85pp
         难负样本决定表征质量上限（业界共识）
Agent 对应：轨迹中的"错误工具选择""绕远路"= Agent 难负样本
         （比随机采样的负例信息量大得多）
可执行：trace → SFT 数据时加一档"低效轨迹"标记（如多调 3 次
         工具才完成的任务），作为难负样本来源
```

### 范式 ④ 覆盖率治理（"复用 ≠ 直接可用"）

```text
搜索案例：Query 覆盖率 73.61% → 89.81%（迁移第一道关卡）
         样本分布必须重新圈选，模型参数可复用不代表覆盖可复用
Agent 对应：工具/场景覆盖率——新场景复用 Agent 时，先查
         "这个场景的输入 Agent 见过多少"
可执行：任何 Agent 场景迁移，第一步输出覆盖率报告
         （query 覆盖率 + 工具调用覆盖率）
```

### 范式 ⑤ 能力注入演进（harness 接口设计）

```text
搜索演进：底层拼接（参与特征交叉，丢连续信息 +18bp）
        → 顶层注入（保信号，不参与交叉 +8bp）
        → PEPNet 门控（自适应调制，最优 +25bp）
本质：模型信号怎么进决策系统——从"固定位置拼接"到"按上下文
      动态调制权重"
Agent 对应：评测分数/语义信号如何影响工具选择——固定权重 vs
         门控式动态加权
可执行：Agent 决策系统里"信号注入"设计为可调机制，
         先拼接验证，再升级为自适应（门控思维）
```

### 范式 ⑥ 迭代节奏（LR + AA + 小流量灰度）

```text
搜索流程：LR（Launch Review）→ 10-20% 流量 7-14 天 → AA 校验
         → 全量
AA 校验的意义：先证明实验系统本身无偏，再读实验差异
Agent 对应：Agent 行为方差大，AA 校验比搜索更需要（同样的输入
         可能因模型随机性结果不同）
可执行：price-agent eval 先跑两遍 baseline，确认评测系统稳定，
         再读实验差异；任何改动走"小范围验证 → 全量"节奏
```

## 四、可执行动作清单（price-agent + 学习计划）

```text
price-agent 落地（方案已设计，见 projects/price-agent-eval-upgrade.md）：
├── ① AA 校验（范式⑥）：baseline 双跑量化评测系统波动，
│      差异 > 波动带才是真信号
├── ② 漏斗指标（范式②）：会话级漏斗（意图→检索→对比→推荐→
│     完成）每层转化率，过程/结果双看
├── ③ 困难集评测（范式③）：20 条语义 Gap query 定向测跨词面匹配
├── ④ 覆盖率统计（范式④）：query 语义覆盖率 + 工具调用覆盖率
└── ⑤ pass@k 指标：区分"能力缺失"（修工具/数据）vs
       "稳定性差"（修 prompt/温度）

学习计划连接：
├── papers/02 美团 Agent 评测 + 本文 = "离线/在线双体系"拼图
│   （02 讲评测方法，本文讲评测在工业项目里怎么落地）
├── papers/06 评测→训练闭环 + 范式③ = 难负样本闭环
├── papers/07 InfoNCE 解剖 = 范式③的数学底座
└── notebook/搜索系统全景 = 检索↔Agent 映射地图
```

## 五、知识树连接

```text
Agent 评测 ← → 搜索评测双体系：离线（AUC/NDCG）+ 在线（AB/AA）——
    美团搜索 = 评测在工业项目落地的完整案例
Agent 评测 ← → 指标归因：过程 vs 结果指标（QV 降 QV_CTR 升案例）
RL Data ← → 难负样本：Agent 轨迹低效路径 = 搜索"曝光未点击"同构
Harness ← → 信号注入：拼接→分桶→门控演进 = 模型能力进系统的接口设计
Agent 评测 ← → AA 校验：方差大的系统先验无偏再读差异
```
