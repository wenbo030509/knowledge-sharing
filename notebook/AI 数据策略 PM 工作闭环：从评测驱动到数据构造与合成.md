## 零、一张图：AI 数据策略 PM 的工作闭环

```text
              ┌──────────────────────────────────────────────┐
              ↓                                              │
[① 驱动源]  评测/gap ──→ [② 发现改进点] 归因 ──→ [③ 决策] 数据策略响应
  能力差距      (哪个维度/难度/环节弱)      (根因分类 + 消费路径分流)
              │                                              │
              │                                              ↓
[⑥ 迭代] ←── [⑤ 验证] 评测+归因 ←── [④ 落实] 数据构造/合成 → 训练
  归因指向         (单变量/before-after/防泄漏)    (采什么/怎么造)

一句话：评测暴露 gap → 归因定位 → 数据策略响应 → 造数据训练 → 再评测。
```

## 一、工作驱动是什么？来源哪里？（Q1）

### 核心答案：驱动 = 能力 gap；源头 = 评测

策略 PM 的工作不是「有需求就写 PRD」，而是被一个 **能力差距（capability gap）** 驱动：

```text
驱动 = 目标能力 − 当前能力

让这个 gap 变得"可见 + 可行动"的仪器 = 评测。
所以"评测驱动"不是口号，是这个岗位的引擎本身。
```

### gap 的五个信号源（按「一手性 / 不可替代性」排序）

```text
① 评测 bad case / 归因 ★最一手★
   └── 你的评测集在哪个维度、哪个难度段掉分
   └── 为什么不可替代：别人的论文里没有你的业务短板
② 下游消费方 / 业务反馈
   └── 训练/产品团队报"模型在 X 场景不行"
③ 能力地图缺口（Capability Map vs 现状）
   └── 对照该会的清单，哪些还不会（↔ papers/10 Brench 能力地图）
④ 模型换代失配
   └── 换基座后哪些维度跌了（换代 = 能力权重重新分布，↔ notebook/LLM 数据集全景）
⑤ 前沿信号（论文 / 竞品）
   └── "这个能力现在可做了 / 有更好的做法"

前四个是内生驱动（你的系统告诉你缺什么），第五个是外部信号。
护城河在内生驱动——尤其①评测归因，那是别人拿不到的一手信息。
```

> **面试锚点**：「我的工作不是等需求，是被评测暴露的能力 gap 驱动——评测既是我发现问题的仪器，也是我验证效果的标尺。」

## 二、如何发现模型有哪些改进点？（Q2）

### 关键：不是「模型不好」，而是定位到「能力维度 × 难度段 × 错误环节」

```text
维度化评测（不是单一通过率）→ 哪个能力维度分最低
    ↓
错误地图（error map）→ base 模型跑全量，聚合错误分布
    （↔ vlm-sft-pipeline-review 主题1：轨迹对比）
    ↓
错误环节分层 → 错在感知层 / 推理层 / 格式层？（这一步决定动作方向）
    ├── 感知层错 → 加视觉/证据类数据
    ├── 推理层错 → 加 CoT / 过程监督数据
    └── 格式层错 → 改评测规范或答案格式规范（不是加数据！）
    ↓
难度分层 → 哪个难度段掉分（长视频 / 长尾 / 计数）
    ↓
pass@k vs pass@1 → 能力缺失（根本不会）vs 稳定性差（偶尔对）
    （↔ projects/price-agent-eval-upgrade：能力 vs 稳定性判别器）
```

### 一条铁律：先修评测误伤，再归因数据

```text
"答对但被判错"的假失败会污染整个归因（↔ notebook/vlm任务2rubric 第十章）：
数字转写缺失 / 多数字取第一个 / 时间格式不全 → 让好数据背锅。
所以归因第一步不是看模型，是先确认评测规范没在误伤。
```

## 三、发现改进点以后怎么做？（Q3）

### 第一步：判断根因类型（决定动作）

```text
四类根因 → 四类动作（↔ notebook/算法反馈迭代）：
├── 任务定义问题 → 修标准 / 补示例 / 调 prompt 模板
├── 数据源问题   → 补关键词 / 换源 / 调配比
├── 标注执行问题 → 补标注指引 / 定向培训 / 质检前置
└── 评测规范问题 → 调容差 / 修判分代码 / 加排除项
```

### 第二步：判断消费路径（不是所有 gap 都要训练！）

```text
数据消费分流（↔ notebook/AI 数据策略）：
├── 知识变化快        → RAG（挂外部，不进参数）
├── 流程固定可抽象     → Skills / Tool（编码成操作知识）
└── 能力缺口（真的不会）→ 才训练（进参数）
分流标准：变化频率 × 需求性质 × 迭代成本 × 可控性
```

### 第三步：若要训练，走数据策略五问

```text
采什么 / 从哪采 / 怎么用 / 怎么验证 / 优先级（↔ notebook/AI 数据策略）
→ 落到"定向构造 / 合成什么数据"（见第六节）
```

## 四、idea 来源于最新的公开论文吗？（Q4）

### 答案：论文是来源之一，不是唯一，而且有陷阱

```text
idea 五来源：
├── bad case（一手，最不可替代）
├── 业务/下游需求
├── 数据洞察（你在数据里看到的 pattern）
├── 竞品 / 模型对比
└── 公开论文 / 前沿  ← 你问的这个，只是其中一个
```

### 论文的正确位置 & 两个陷阱

```text
位置：论文是"别人已经验证过的解"，一手 bad case 是"还没人解的真问题"。
     差异化在后者——选对问题 > 解问题（↔ papers/08 Research Taste）。

陷阱1（蒸馏 loop）：只抄论文 = 跟随式学习，追到 frontier 才发现
     缺独立解难题的能力（↔ papers/09 手记）。
陷阱2（reward hacking / 反 bitter lesson）：只优化局部信号、
     堆人类先验而非靠数据+算力，本质是 reward hacking（↔ papers/09 + Reward Model 解剖）。

正确用法：论文当"方法工具箱 + 灵感源"，但**问题必须来自你自己的评测/业务**。
```

## 五、如何落实 idea 的执行？（Q5）

### 执行闭环：idea 到落地

```text
idea
 ↓  转成可证伪假设（"补 X 类数据 → Y 能力 +Z"）
假设
 ↓  MVP 小批先验证方向（不要一上来大规模！）
小批验证
 ↓  数据构造 / 合成（见第六节）
造数据
 ↓  训练（SFT / DPO / RL，loss 只在 response token）
训练
 ↓  评测 + 归因（单变量 / before-after / 防泄漏 / 护栏指标）
验证
 ↓  方向对 → 扩量；方向错 → 回滚重新归因
迭代
```

### 具体实例：靶向 SFT 三步闭环（我亲历的落地样本）

```text
（↔ projects/vlm-sft-pipeline-review）
① 轨迹对比（诊断）→ base 模型跑全量，定位错题 = 错误地图
② 行为引导 Rollout（造数）→ 拒绝采样合成正样本
③ SFT（模仿）→ loss mask + teacher forcing
验证：覆盖子集 +2.8（方向对）→ 下一轮按覆盖率 45% 缺口扩量
```

### 四条执行纪律（面试深度所在）

```text
├── 小批先验证方向：MVP 证明"补这类数据有用"，再投大规模
├── 单变量原则：一次只改一个变量，涨了归因明确、跌了回滚明确
├── 防数据泄漏：训练/评测数据隔离——归因成立的前提
└── 护栏指标：防"按下葫芦浮起瓢"（新能力涨、旧能力降 = 难度坍缩/灾难性遗忘）
```

## 六、数据构造 vs 数据合成（Q6）★ 本次补充学习重点

### 6.1 一句话区分

```text
数据构造（Data Construction）：上位概念——"生产训练样本"的总活动，
    强调【设计 + 组织】。素材可真可假，核心是"设计任务 + 组织素材"。

数据合成（Data Synthesis）：其中一种手段——数据（或其一部分）由
    模型/程序【自动生成】，而非真实采集。强调【生成】。

关系：合成 ⊂ 构造。真实管线常"构造中含合成"
     （真实视频采集[构造] + LLM 生成初版 CoT[合成] + 人工终审）。
```

### 6.2 最本质的分辨轴：signal/ground-truth 从哪来

```text
真实采集（real）  ： 从世界/日志/用户采集 + 人工标注 → 真实但贵、慢、稀缺
合成生成（synthetic）：模型/程序生成 → 快、可规模化，但可能失真、需验证

判断一条数据是"构造"还是"合成"，问：它的答案/信号是采来的还是生成的？
```

### 6.3 数据合成方法谱系（按生成器分四类）

```text
① 模型合成（LLM/VLM 生成）
   ├── Self-Instruct / Evol-Instruct：种子指令 → 进化出更多/更难指令
   │   （Alpaca / WizardLM）
   ├── 蒸馏（Distillation）：强/教师模型生成答案/CoT/偏好训小模型
   ├── 拒绝采样 / RFT / STaR：自采样多条 + 筛选正确的进训练集
   │   （★我做过：行为引导 Rollout = 这个，vlm-sft-pipeline-review 第六节）
   └── 反向构造（back-translation）：从答案反推问题（从代码反推需求）

② 程序 / 规则合成（Programmatic）
   ├── 模板/规则生成：数学题、SQL、结构化任务（答案可程序验证）
   ├── 数据增强（augmentation）：改写、扰动、同义替换
   └── Bug 注入：程序化制造可验证 bug（★SWE-smith，papers/06：128 仓库 → 52k 实例）

③ 仿真 / 渲染合成（Simulation / Rendering）
   ├── 扩散模型 / GAN 生成图像 → 图文对（★gap-analysis D3 待补方向）
   ├── 渲染 / 游戏引擎：自带 ground truth（深度/分割/3D），视觉数据
   └── 物理仿真：机器人 / 世界模型数据

④ 环境交互合成（Environment Rollout）
   ├── Agent 在可重置环境里跑 → 轨迹（agentic data，papers/09：环境组已超建模组）
   └── RL rollout（harness 同时是 rollout 环境，↔ Agent Harness 解剖）
```

### 6.4 合成的命门：verifier / filter（没有验证的合成是危险的）

```text
合成数据必须配验证器，否则幻觉/错误直接污染训练：
├── 可验证任务（数学/代码）→ 程序自动验证 → 高质量合成（RLVR 的基础，DeepSeek-R1）
└── 不可验证任务（开放生成）→ LLM judge / 人工 / 拒绝采样 → 更贵、更易引入偏差

★这正是我质检经验的价值迁移：
  拒绝采样的"筛选" = 我的质检 Gate（内容准确/过程合规/格式规范）
  合成的质量天花板 = 验证器的可靠性（↔ LLM Judge 可靠性，papers/05）
```

### 6.5 合成的五个风险（面试追问准备）

```text
① 幻觉/错误   → LLM 编造不存在的内容。对策：verifier 兜底
② 分布失真   → 合成分布 ≠ 真实分布（"合成快但分布失真"，gap-analysis）
③ 模型坍缩   → 反复用模型输出训模型 → 多样性递减、分布收窄、长期退化
                （model collapse）。对策：掺真实数据、控制合成比例
④ 多样性不足 → 合成易同质化。对策：受控变异（papers/10 Brench：
                LLM 只在规定维度变异）、温度/种子多样化
⑤ 反捷径/泄漏 → 引入 shortcut（VLM language shortcut）或与评测集重叠（污染）
```

### 6.6 构造 vs 合成的选择框架

| 情况 | 倾向 |
|------|------|
| 分布必须对齐真实世界 | 真实构造 |
| 需要可追溯 / 合规（涉密） | 真实构造 |
| 任务可自动验证（数学/代码） | 合成（性价比极高） |
| 规模化、成本敏感 | 合成 |
| 冷启动、无真实数据 | 合成 + 少量真实种子（↔ papers/10 金种子 + 受控变异）|
| 长尾/稀缺能力，真实采不到 | 合成/构造对齐难度（防难度坍缩）|
| **最佳实践** | **真实打底 + 合成扩量 + verifier 兜底** |

### 6.7 关键证据：数据质量+规模可换参数量

```text
↔ papers/06：32B 微调 + 5k 高质量合成数据，在 SWE-bench Verified 上
   打败 235B 未微调模型（40.2% Pass@1，开源 SoTA）。
Phi 系列（"Textbooks Are All You Need"）：高质量合成数据训小模型打败大模型。
→ 这是"数据策略 PM 价值"的最硬证据：造对数据 > 堆参数。
```

## 七、测试模型能力边界（capability probing）★ PM 核心工作

> 补充：这是策略 PM 非常重要的一块工作。它不是「② 发现改进点」的重复，而是它的**主动升级版**——
> 不等 bad case 冒出来，而是主动去「压」模型，找出它从哪里开始失败。

### 7.1 什么是能力边界

```text
能力边界 = 模型"从哪里开始崩"的轮廓线。
├── 不是问"对不对"（那是通过率）
└── 是问"到什么难度 / 什么分布 / 什么组合，就开始掉分"

为什么是 PM 核心工作：
├── 边界定义了"下一步该往哪推"——不知道边界，就不知道该造什么数据
├── 边界 = 能力 gap 的精确形状（发现改进点的高级形态）
└── 面向产品/客户时，边界 = 风险地图（哪些场景不能保证 → 护栏）
```

### 7.2 四类探测方法

```text
① 难度升级探测（difficulty escalation）
   └── 沿难度轴加压直到掉分，找拐点
   └── ↔ 难度坍缩 / Video-MME 长视频掉分 / MMMU→MMMU-Pro 掉 17-27%
② 分布外探测（OOD / distribution shift）
   └── 换到训练没见过的分布 → 测真泛化（↔ WildClaw 野外集就是这个）
③ 组合 / 长程探测
   └── 单点都会、组合起来崩（多跳推理、长程 Agent 任务）
④ 对抗 / 边缘 case
   └── distractor、歧义、矛盾输入（↔ price-agent P3 能力边界 + 评测规范排除项）
```

### 7.3 用公开 benchmark 探边界的正确姿势 + 三个陷阱 ★

> 你的原始理解：「训练好的模型 → 用最新公开论文的 benchmark 评测 → 发现缺陷 → 针对低分能力训练」。
> 主干对，但这条链路藏着三个陷阱——**懂评测的人知道 benchmark 什么时候会骗你**，这正是深度所在。

```text
陷阱①：数据污染（contamination）
   └── 最新 benchmark，模型训练时可能已"见过" → 分数虚高，掩盖真实边界
   └── ↔ SWE-bench Verified 因污染被 OpenAI 2025-12 停用
   └── 对策：公开榜必须配"自建困难集 / 业务评测集"交叉验证

陷阱②：通用榜 ≠ 业务边界
   └── 通用榜的边界 ≠ 你业务场景的边界（↔ Warren Optima：
       公共 benchmark 与业务 benchmark 互补非替代）
   └── 对策：真实边界靠业务评测集精确定位

陷阱③：得分低 ≠ 能力缺陷
   └── 可能是评测误伤（格式/解析）或 benchmark 分布不符
   └── 对策：先修评测误伤再归因（↔ 第二节铁律）——否则"针对低分训练"
       会把评测 bug 当能力缺口，白造一批数据

结论：公开 benchmark 是"能力边界的第一张地图"，
     但真实边界 = 公开榜 + 自建困难集 + 业务评测集 + 归因。
     ⚠️ 还要防 Goodhart：直接对着 benchmark 分布训练 = 刷榜，
        涨的是分数不是能力（↔ 第五节·三类 PM 目标商榷）。
```

### 7.4 边界探测 vs 回归评测（攻守两面）

```text
边界探测 / 能力评测（攻）：通过率应"低"才有区分度，探未知边界
回归评测（守）：通过率应≈100%，防已有能力退步
↔ papers/01 Anthropic：能力评测 vs 回归评测，两套目的相反的评测
```

## 八、探索 → 放量：小批验证方向，大批规模化 ★

> 你的原始理解：「早期 PM + 算法用小批量训练集做测试，取得提升了，就落到下游用大批量数据集训练提升能力」。
> 这是标准的 **MVP-then-scale**，也正好是你 VLM 项目的工作方式——我把它拆细，并补上你没提到的放量风险。

### 8.1 二阶段结构

| 维度 | 探索期（probe / PoC） | 放量期（scale / production）|
|------|----------------------|----------------------------|
| **谁做** | PM + 算法 共做 | 数据团队（我）主导生产 |
| **数据量** | 小批（百~千） | 大批（万~十万） |
| **目标** | 验证方向有效性 | 覆盖率 + 规模化能力提升 |
| **不确定性** | 高（可能被证伪） | 低（方向已验证） |
| **工作方式** | 快速试错 = 实验科学 | 定向构造/合成 + 质检 + 交付 = 生产 |
| **产出** | +delta 信号（值不值得放量）| 能力的真实、规模化提升 |

**这张表和三类 PM 的分野同源**：探索期 = 实验科学模式（Research Taste，可能证伪），放量期 = 数据生产模式（覆盖率、规模化）。策略 PM 两段都参与，但**放量期的数据生产是我的主战场**。

### 8.2 为什么必须先小批（渐进式投资）

```text
大批量训练很贵（GPU + 标注 + 时间）→ 先用小批以最低成本验证
"这类数据有没有用"，避免在错误方向上大规模投入。
↔ baidu-agent-migration 3.4 后训练决策公式：业务价值未验证不预支成本。

⚠️ 小批验证的是【方向有效性】，不是【最终提升幅度】。
   小批 +delta = "值不值得放量"的决策信号，不是终值。
```

### 8.3 放量的三个陷阱（你没提到但关键）★

```text
① 非线性放大：小批 +2.8 ≠ 大批线性涨
   └── ★活案例就是你自己：VLM 靶向 SFT 覆盖子集 +2.8，
       全量被 89 题未覆盖稀释到 +0.5（vlm-sft-pipeline-review 8.4）
   └── 放量收益随覆盖率向子集收益收敛——瓶颈是覆盖率不是质量
② 小批过拟合：小批可能过拟合到特定分布，放量才暴露泛化问题
   └── 对策：小批阶段就用 held-out / 野外集验证泛化（WildClaw +2.3 的意义）
③ 放量引入新问题：规模化后灾难性遗忘 / 难度坍缩 / 分布偏移
   └── 对策：放量期也要挂护栏指标（未覆盖能力不许跌）+ 混通用数据
```

### 8.4 映射你的 VLM 项目（面试即取即用）

```text
探索期：PM + 算法用小批三元组 SFT → 覆盖子集 +2.8（方向验证成功）
    ↓ 决策：方向对，值得放量
放量期：我在下游用大批量数据集定向构造/合成 + 质检 + 交付
    ↓ 按覆盖率 45% 缺口扩量，补未覆盖的 89 题弱项
预期：全量收益随覆盖率提升，向子集收益（+2.8）收敛

一句话讲清：早期小批只是验证"补这类数据有用"，
           真正的规模化能力提升靠下游放量——而放量不是简单加量，
           要盯覆盖率、防稀释、挂护栏，这才是数据生产的活。
```

## 九、被动补洞 vs 主动抬天花板：模型能力的主动提升

> 你的洞察：前八节的「评测驱动迭代」本质是**被动**的——靠更难的题、新 benchmark 暴露不足再补洞。
> 但行业里模型架构在演进、能力在主动跃升。这一节回答：主动进步从哪来、各角色怎么发力、PM 怎么切入。

### 9.1 先纠一个前提：被动的不是「评测驱动」，是「回看型评测」

```text
被动（gap-driven / 补洞）：
   回看已知失败 → 归因 → 补洞。天花板 = 已知问题集的边界。
   —— 前八节讲的就是这个，它只能让你逼近「已知问题的前沿」。

主动（lever-driven / 抬天花板）：
   前瞻押注某个杠杆 → 受控实验 → 扩张能力空间本身。

★关键：主动进步不是「不测」，而是被另一种信号测——
   ablation（消融）+ scaling curve（规模曲线）+ 前沿能力探针，
   而不是 business bad case。两者都是实验科学，区别在：
   被动 = 向后归因失败，主动 = 向前押注杠杆。

→ 所以「评测驱动」本身不分主被动。评测既能当【补洞探测器】（回看），
  也能当【抬天花板指南针】（前瞻）。区别只在你的评测是「回看已知失败」
  还是「前瞻定义还没人做的新能力」。⭐这正是 PM 主动性的最高杠杆（见 9.4）。
```

### 9.2 主动进步的五个杠杆（Q1：主动动作从哪来）

```text
模型能力 = f(数据, 架构, 目标函数, 算力)——前四个是基础杠杆，第五个是重组它们的范式：

① 算力 / 规模（Scaling）★历史最大驱动
   └── the bitter lesson：赌规模而非堆人类先验；Scaling Law（Chinchilla）
       给出回报曲线的形状 → 押注曲线本身就是「主动」
② 架构（Architecture）
   └── Transformer → 注意力变体 → MoE 稀疏激活 → SSM/Mamba → 混合；
       长上下文 / 效率 / 容量
③ 训练范式（Training Paradigm）
   └── next-token → SFT → RLHF → DPO → RLVR → 推理 RL（o1/R1）；
       从「模仿」到「搜索 / 自我改进」是范式跃迁（↔ 靶向 SFT / Reward Model 解剖）
④ 数据范式（Data Paradigm）★你的主战场
   └── 网爬 → 精选 → 合成 → 自生成（STaR / 大规模拒绝采样）→ 环境交互轨迹；
       Phi「Textbooks」：质量>数量，数据本身是主动杠杆（↔ 第六节）
⑤ 推理时计算（Test-time Compute）2024 新轴
   └── o1 式：推理时花更多算力（CoT / 搜索 / self-consistency / best-of-n）
       —— 一条全新 scaling 轴，不改参数也能抬能力
⑥（元杠杆）目标函数创新：优化什么 = 能力长什么样
   └── 过程奖励 vs 结果奖励 / 可验证奖励（↔ reward = 评测标准可执行化）
```

> 诚实标注：②③⑤是算法/研发主导的杠杆，我理解到「是什么、动哪个方向」这一层；
> 能亲手动的是 ④ 数据范式。面试讲这些要分清「我了解的杠杆地图」和「我做过的数据杠杆」。

### 9.3 要不要系统读各家模型论文（Q2）+ 算法怎么把理论变行动（Q3）

**Q2 —— 要读，但用「造地图」的姿势读，不是抄：**

```text
├── 论文给你两样东西：方法工具箱 + 前沿地图（别人拉过哪个杠杆、什么有效）
├── 但纯跟论文 = 蒸馏 loop（↔ papers/09）：追到 frontier 才发现没有独立解题能力
├── 正确姿势（↔ 精读拆解方法论 事实-过程-方法三层）：读「方法层」（可迁移原则），
│   不背事实；把每篇论文 slot 进「五杠杆地图」（架构/数据/目标/RL/推理时）
└── 对 PM：不需复现，但要读到「why / 动了哪个杠杆」层，才能①判可行性
    ②发现哪个前沿 idea 能映射到你的业务问题 ③和算法对话
系统 ≠ 全读。系统 = 按五杠杆建结构化地图、每篇归位（= 知识树做法）。
```

**Q3 —— 算法把理论变行动的链路（我理解的框架，需与算法同学核实）：**

```text
理论/idea → 可证伪假设 → 最小实验（小模型/小数据先验证机制）
    → ablation 隔离变量（证明是这个改动带来的）
    → scaling 验证（小规模趋势能否外推到大规模）
    → 集成进训练 recipe → 回归防退化

核心方法：先在小规模做受控实验证明机制有效，再赌规模化；
         读的是 loss 曲线 / 能力涌现，不只终分。
↔ 这和你的「小批验证→放量」（第八节）同构，只是发生在【研究】层而非【补数据】层。
```

### 9.4 PM 如何主动把产品/用户需求变成模型能力方向（Q4）★本节核心

> PM 不动架构/目标函数杠杆（算法动），但 PM 动的是**「往哪个方向抬天花板」的杠杆——定义目标**。
> 而「选对方向」往往是最高杠杆（选对问题 > 解问题，↔ papers/08）。

```text
PM 的四个主动杠杆：

① 前瞻能力地图（forward capability map）
   └── 不等 bad case：设计产品 6-12 个月后「应该会」的能力，
       现在没需求但很快成瓶颈的能力 → 提前定为数据/评测目标
   └── = Research Taste 用在产品上：判断哪个能力半年后成瓶颈

② 需求 → 能力规格（needs → capability spec）★PM 独有
   └── 用户需求「帮我规划一次旅行」→ 拆成能力（长程规划/工具使用/
       约束满足/记忆）→ 每个变成一个数据 + 评测目标
   └── 只有 PM 同时看到「原始用户需求」和「能拆成哪些模型能力」

③ 造新评测 = 定义新能力方向（authoring the next eval）★最深的主动动作
   └── 给一个还没有评测的能力建评测（真实任务/agentic/长程，
       ↔ papers/03/10/12：稀缺 = 蓝海）
   └── 你亲手定义的新评测 = 你给全团队指的新北极星 →
       「评测驱动」从被动补洞变成主动抬天花板（呼应 9.1）

④ 数据范式创新（data paradigm）★你的主战场
   └── 提出解锁新能力的新数据来源/构造方式：Agent 轨迹数据、
       合成数据管线、用户纠正飞轮（↔ 第六节 + 数据策略五问）

一句话：PM 的主动杠杆 = 定义目标（能力地图 / 新评测 / 目标分布 / 数据范式）。
       算法负责「怎么抬」，PM 负责「往哪抬」。
```

### 9.5 综合切入点与实施路径（Q5）

```text
对你（评测×数据 PM）性价比最高的主动切入点，按杠杆排序：

切入点 1：造新评测定义新能力（最高杠杆，蓝海）
   └── 真实任务/agentic/长程评测集——别人没测的能力 = 你指的新方向
切入点 2：数据范式创新
   └── 轨迹数据 / 合成管线 / 用户纠正飞轮 → 解锁新能力
切入点 3：前瞻能力地图
   └── 把用户需求拆成 6-12 月后的能力清单，提前布数据
切入点 4：参与 objective 设计
   └── 评测标准可执行化 = reward（↔ Reward Model 解剖），
       让做评测的人天然理解 RL 数据需求

实施路径（前瞻版闭环，对照第零节回看版）：
前瞻假设（这能力该做了）→ 定义评测/能力目标（authoring）
   → 小批数据验证方向 → 与算法协作实验（他们动 arch/objective 杠杆）
   → scaling 放量 → 回归防退化 → 新地图

面试锚点：
「评测驱动看起来被动，是因为评测在回看已知失败。但当我主动 authoring
下一张评测和能力地图时，同一套机器就变成了主动抬天花板的引擎——
我定义的新评测，就是团队的新北极星。PM 不动架构和目标函数，但动
『往哪个方向抬』这个最高杠杆，而选对方向往往比解问题更值钱。」
```

## 十、面试故事（30 秒 / 2 分钟）

### 版本 A（30 秒）

> AI 数据策略 PM 的工作是被评测暴露的能力 gap 驱动的：评测归因定位到模型在哪个能力维度、哪个错误环节弱 → 判断是加数据还是改 harness → 要加数据就走数据策略五问，定向构造或合成 → 训练后 before/after 对照验证。idea 主要来自一手 bad case 而非论文——论文是别人验证过的解，bad case 才是没人解的真问题。落实的纪律是小批先验证方向、单变量、防泄漏、护栏指标。

### 版本 B（2 分钟）—— 补数据构造/合成

> 数据这块我区分构造和合成：构造是从真实素材设计任务（我做过 VLM 考点先行寻源、Price-Agent 的 Trace→SFT），合成是用模型或程序自动生成（我做过行为引导 Rollout，本质是拒绝采样——采样多条、筛选出答案对且过程合规的进训练集）。
>
> 合成的命门是验证器：可验证任务（数学、代码）能程序自动判分，合成性价比极高，DeepSeek-R1 的 RLVR 就是这个；开放任务只能靠 LLM judge 或人工，更贵也更易引入偏差——这正好是我质检经验能迁移的地方，拒绝采样的"筛选"就是我的质检 Gate。合成还有分布失真、模型坍缩、多样性不足几个坑，所以最佳实践是真实打底 + 合成扩量 + verifier 兜底。有个硬证据我印象很深：32B 模型加 5k 高质量合成数据能在 SWE-bench 上打败 235B 未微调模型——造对数据比堆参数更有杠杆，这就是数据策略 PM 的价值。
