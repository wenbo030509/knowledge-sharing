## 二、八层解剖（以"VLM 评测基准"为对象，四者横向对比）

### ① 它是什么？

VLM 评测基准 = 衡量视觉-语言模型（VLM/MLLM）能力的标准化"考试"。四个代表覆盖了四种设计哲学：

```text
MMMU：考专家级学科推理——用大学考试题把模型当"准专家"考
MME：考感知底盘的完整性——14 个子任务逐项盘点
Video-MME：考视频特有的时间/多模态综合能力——目前唯一全谱系视频基准
MMBench：考能力维度的分布——20 维雷达图，看偏科
```

**算法视角**：它们测的能力层次不同——MMMU 需要感知+知识+推理三者协同（错误分析显示 GPT-4V 的错误 35% 感知 / 29% 知识 / 26% 推理），MME 把感知和认知分开计分，Video-MME 区分感知类/推理类/信息摘要类任务，MMBench 直接按能力维度计分。

### ② 为什么出现？

**PM 视角**：2023 年前 VLM 评测散乱——每篇论文自造样本、自定指标，分数不可比，产品选型没有标尺。评测基准就是把"什么是好模型"公共化、标准化。

分水岭动机有三个：

```text
1. 从"感知"到"理解+推理"：早期基准（图像分类式）测不出推理；
   MMMU 用大学级题目把门槛抬高到"需要专业知识"
2. 视频被严重低估：图像模型抽帧就能"看视频"——但这丢了时间
   推理；Video-MME 要逼出真正的视频能力（时长越长性能越差是
   所有模型的共性，这就是时间推理的信号）
3. 需要可复现、可扩展的公共标尺：公司选基座、开发者选模型、
   研究社区追踪进步，都需要同一把尺子
```

**算法视角**：MMU 发布时人类专家基线 76-89%，GPT-4V 只有 56%——这说明基准设计时"天花板"是清楚的，差距可量化。评测基准的价值就在于**把能力差距变成可追踪的数字**。

### ③ 数学原理是什么？

评测基准的"数学"在统计设计而非模型公式：

```text
├── 指标：准确率（MC 题）；MME 的 accuracy+ = 答对且不误报的
│   综合（yes/no 二元任务里，模型答"yes"容易，必须惩罚误报）
├── 样本设计：Video-MME 2700 题答案 A/B/C/D 均匀分布（≈25%）
│   ——防止模型靠位置先验蒙对；MMMU 难度分层 Easy/Medium/Hard
│   （28%/45%/27%）——保证区分度
├── CircularEval（MMBench）：同一道题把选项打乱重测 N 次，
│   全对才算对 → 消除"位置偏差"的统计手段（代价：推理成本 ×N）
└── 数据泄漏防护：MME 全部手写题目避免复用公开数据集；
   Video-MME 质量过滤保证"只看文本答不出"（文本-only < 15%）
```

**算法视角**：这里没有复杂的优化目标，但有一个关键设计——**答案分布的统计特性决定了基准的可靠性**。答案不均匀 → 位置偏差污染指标；题目可被文本回答 → 测的是语言不是视觉。这些与判分规范里的"distractor 排除"是同一思想（rubric 5 部件）。

### ④ 工程怎么实现？

四个基准的数据管线与判分管线：

```text
数据收集管线：
├── MMMU：约 50 名大学生从大学教材/测验/考试手工收集，
│   30 种图像类型（图表/化学结构/乐谱/医学影像…）
├── Video-MME：YouTube 人工收集 + 人工标注，
│   覆盖 11 秒 ~ 1 小时（短 <2min / 中 4-15min / 长 30-60min），
│   713 个视频带字幕、869 个带音频
├── MME：题目全部手动设计（避免泄漏），指令统一
│   "请回答 yes or no"（多选项指令当时模型跟随不了，用二元）
└── MMBench：GPT-4/Gemini-Pro 投票生成候选 + 人工校验

判分管线：
├── 简单基准：规则匹配选项（对不齐就误判）
├── MMBench 两阶段提取：规则匹配先行 → GPT-4 fallback
│   把自由文本预测映射回选项（与人类一致率 91.5%）
│   ——这就是"LLM-as-judge 兜底规则匹配"的工程实现
└── Video-MME 双设置：无字幕（纯帧）/ 有字幕（字幕转录前置
    到 prompt）——显式控制输入模态，可归因字幕带来的增益
```

**工程视角**：注意 MMBench 的判分管线与 rubric 判分五模式的同构性——先规则、后模型兜底（Deterministic Floor）。而"规则匹配 → LLM fallback"正是 papers/05 里"确定性优先、LLM 兜底"的落地方案。

### ⑤ 为什么有效？

```text
├── 难样本逼推理：大学级题目（MMMU）让"记忆型"与"推理型"
│   模型拉开差距；开源的 34% vs GPT-4V 56% vs 人类 89%
├── 维度覆盖防偏科：MMBench 20 维雷达图直接暴露"哪些能力弱"，
│   比单指标更有诊断价值
├── 视频长度是天然的难度分层：Video-MME 显示所有模型时长越长
│   掉分越多——长视频需要的跨段整合是模型的共性短板
│   （← 连接你工作的"长视频跨时段整合"）
└── 可复现判分：MC + 规则/LLM 提取，保证分数可复现可追踪
```

**策略视角**：基准有效的最终证据是——它能区分模型、能追踪进步（MMMU 从 56% → 87%，逼近人类 88.6%），并在饱和后自我演化（MMMU-Pro 掉 17-27% 重新拉开差距）。一个测不出差别的基准就是失效的基准（对照 SWE-bench 的框架效应教训）。

### ⑥ 为什么不用别的方法？

```text
├── 人类评分：准确但慢/贵/不一致 → 标准化 MC 换扩展性
├── 纯 LLM judge 判分：有偏差（位置/冗长）→ MC 用规则/提取器
│   判分更稳（MMBench 的 GPT-4 fallback 只处理边界情况）
├── 抽帧退化评测：图像模型抽帧看视频 ≠ 测视频能力 → Video-MME
│   用整段视频 + 时长分层逼出时间推理（字幕/音频显式控制）
├── 生成式回答 vs MC：开放回答信息量大但难判分 → MC 牺牲表达
│   自由换判分可靠（MMMU 只留 6% 开放题）
└── 自造评测集 vs 公共基准：自造贴近业务但不可比 → 公共基准
    承担"外部标尺"，业务集承担"选型依据"（↔ 知识树 Business
    Eval Set：谁掌握业务评测集，谁有换基座否决权）
```

### ⑦ 工业界怎么做？

```text
├── 登顶史：GPT-4V 56% → Gemini Ultra 59%（2023 末）→ 2026 年
│   top 模型 85-87%，逼近人类专家 88.6%——评测卡是发布会标配
├── 饱和与换代：MMMU 四选一饱和 → MMMU-Pro（开放格式+更难题）
│   掉 17-27%，与 MMLU → MMLU-Pro 同一条演化路径
├── 视频评测现状：Kimi K3 在 Video-MME 有字幕设置达 90.0%
│   （2026.07）——视频基准还在拉开差距阶段，未饱和
├── 开源评测平台：OpenCompass / EvalScope / HuggingFace
│   lmms-lab 统一跑分入口——评测基建本身产品化
└── 业务落地：公司内部用公共基准做"基座选型 + 换版回归"，
   业务评测集做"能力子分布验证"（通用榜 ≠ 业务分布）
```

### ⑧ 和整个 AI 系统怎么连接？

**这是最相关的一层——直接对接你的工作：**

```text
VLM 数据生产 ← → 评测基准地图：
├── Video-MME 字幕设置 ← → 你的 M015/M016 字幕 OCR 数据：
│   评测显式控制"字幕轨是否给模型"——数据生产里的字幕轨
│   就是评测里的证据边界（rubric 5 部件）
├── "文本-only 答不出"质量过滤 ← → 证据边界设计：
│   评测题保证"答案只能从视觉/视频来"——与你质检的
│   "答案能否从素材验证"同一原则
├── 长视频掉分共性 ← → VLM 长视频数据生产：
│   长视频跨时段整合 = 模型共性短板 = 数据生产的价值洼地
│   （你 VLM 多视频项目的 L2/L3 跨视频能力直接对应）
└── 判分管线（规则 → LLM fallback）← → 判分五模式：
    同一套 Deterministic Floor 思想
```

知识树连接：`VLM 评测基准 ← → Benchmark Design`、`Video-MME ← → 视频数据 Pipeline / Video SFT Data`、`字幕轨 ← → 证据边界`。

## 三、Video-MME 深读（与工作最相关）

```text
设计三件套：
├── 时长分层：11s ~ 1h，按 短/中/长 报告准确率——不同时长
│   对应不同能力（短：单事件感知；长：跨段整合+信息摘要）
├── 模态控制：帧 / 帧+字幕 / 帧+音频 三档设置——字幕 +5.9%、
│   音频 +4.7%（Gemini 1.5 Pro），知识密集型题和长视频增益最大
└── 质量过滤：2700 题保证文本-only 答不出（<15%）——
    防止"测语言不测视频"

对你的直接启示：
├── 字幕轨是评测的关键证据通道——你做字幕数据生产时，
│   字幕的"纯净度"（无 OCR 噪声/无中英夹杂）直接决定模型
│   在 Video-MME 有字幕设置下的表现（M016 的排除项写法
│   就是为这个服务的）
├── 长视频 = 评测洼地 = 数据价值洼地：1h 视频的训练数据
│   稀缺（难度坍缩案例：示例 1h、标注 10s），而评测恰好
│   在长视频上最能拉开差距——这验证了"难度对齐"的价值
└── 面试可直接讲："我生产的字幕数据对应 Video-MME 的
    有字幕设置；我的质检标准对应它的质量过滤"
```

## 四、三组追问

**算法视角**：准确率在饱和期还有区分度吗？（MMMU 87% vs 人类 89% —— 天花板效应 → MMMU-Pro）；答案均匀分布 vs 位置偏差如何统计消除？（CircularEval）；字幕增益如何归因？（三档模态设置 = 控制变量实验）

**工程视角**：抽帧数量与推理成本怎么平衡？2700 题 × 900 视频的推理成本？判分提取器的规则兜底怎么防误判？（MMBench 91.5% 一致性仍非 100%）；数据泄漏如何持续防？（MME 手写 vs 公开爬取）

**讲述视角**：为什么视频评测比图像评测难？为什么基准会饱和？一个基准"失效"的标志是什么？（测不出差别）；工业界谁在做 VLM 评测？（OpenCompass/lmms-lab）；评测基准怎么反哺数据生产？（能力维度 → 数据方向）

## 五、面试故事（3 句话版本）

> 背景：VLM 评测基准地图缺失——我的 VLM 数据生产工作没有对应的评测坐标系。
> 动作：解剖 MMMU/MME/Video-MME/MMBench 四个代表基准，横向对比数据管线、判分机制和设计哲学，并把 Video-MME 的字幕设置、质量过滤与我的字幕数据生产、质检标准逐条对应。
> 结果：发现评测基准与数据生产是同一枚硬币的两面——评测的能力维度就是数据生产的价值洼地（长视频、跨段整合），字幕轨既是评测的证据边界也是我质检的检查项。

## 六、知识树连接清单

- `VLM 评测基准` ← → `Benchmark Design`：四基准 = 四种设计哲学（学科考试/能力普查/视频综合/维度矩阵）
- `Video-MME` ← → `Video Data Pipeline / Video SFT Data`：字幕轨设置 = 证据边界；长视频 = 数据价值洼地
- `字幕轨` ← → `证据边界（rubric 5 部件）`：评测显式控制模态 = 质检限定证据来源
- `MMBU 饱和 → MMMU-Pro` ← → `SWE-bench 污染教训`：基准有生命周期，饱和/污染都会失效
- `MMBench 规则→LLM fallback 判分` ← → `判分五模式 / Deterministic Floor`：同一套确定性优先思想
- `评测基准` ← → `业务评测集`：公共基准管"可比"，业务集管"选型"
