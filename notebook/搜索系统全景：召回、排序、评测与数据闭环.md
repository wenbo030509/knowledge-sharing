## 零、为什么搜索值得学（30 秒版）

搜索是全行业最成熟的"**意图理解 + 匹配 + 排序**"工业化场景。Agent（RAG 检索、工具选择、意图路由）大量复用搜索的技术栈，搜索的评测方法论（离线指标 + 在线 AB）是 Agent 评测的前驱。作为数据 PM，搜索的"行为日志 → 样本 → 特征 → 闭环"是最完整的范式教材。

## 一、整体链路（漏斗模型）

```text
用户 Query
   │
   ▼
① Query 理解       意图分类 / 实体识别 / 改写纠错 / 长尾分析
   │
   ▼
② 召回 (Recall)    从全库 N 亿 → 几百~几千 候选
   │               三路召回：词面(BM25) + 语义(向量) + 个性化(协同)
   │               目标：求全（Recall@K），错过对的 = 永远排不上
   ▼
③ 粗排 (Coarse)    几百 ~ 上千 → 几百
   │               轻量模型快速过滤，控制精排输入量
   ▼
④ 精排 (Fine)      几百 → 几十~上百
   │               复杂模型 + 全量特征（美团 LLM 表征注入在这层）
   │               目标：求准（NDCG / GAUC）
   ▼
⑤ 混排/重排        多目标权衡（CTR / 订单 / 体验）→ 最终列表
   │               去重、多样性、位置约束
   ▼
展示 → 用户行为（点击/下单）→ 日志
   │
   └──→ ⑥ 数据闭环：行为日志 → 训练样本 → 特征 → 模型迭代 → 上线
```

**每层延迟预算（数量级）：** 召回 <50ms → 粗排 <100ms → 精排 <200ms。美团二期"TP90 仅 +0.2ms"是性能指标的原因——排序链路对延迟极其敏感，加一个特征都可能超预算。

**漏斗的工程含义：** 每一层的代价和精度不同。召回层要用便宜方法捞全（向量近邻搜索），排序层才花大钱算精确分数（复杂模型）。这解释了美团为什么把 64 维表征离线算好存 KV——线上加一次模型推理会超时。

## 二、① Query 理解层

```text
是什么：把用户的一句话翻译成系统能用的结构化信息
├── 意图分类：交易型 / 信息型 / 留资型（美团服务零售背景）
├── 实体识别：抽品类、品牌、价格、场景词
├── 改写/纠错："pad" → "iPad"、"洗牙哪家好" → 意图改写
└── 长尾分析：频次低、词面差的 Query 是语义模型的增值区

怎么判断好坏（数据 PM 视角）：
├── 意图分类准确率 + 错误分布（哪类意图最易混淆）
├── 长尾 Query 占比 = 语义特征收益空间（美团：长尾 NDCG +2.21pp
│   恰好证明长尾是语义建模最薄弱也最有价值处）
└── 覆盖率：有多少 Query 能被理解层完整解析

与 Agent 的连接：意图路由 = price-agent 的 _detect_intent()
├── 规则路由（关键词）vs LLM 判断的 trade-off
└── 多轮 Agent 的"意图保持"= 搜索的 query 改写 + 上下文继承
```

## 三、② 召回层（Retrieval）

```text
是什么：从全库快速捞候选。三路并行，结果融合
├── 词面召回：倒排索引 + BM25（词频/逆文档频率）
│   ├── 优点：精确、可解释、无冷启动
│   └── 缺点：语义 Gap——"宠物 SPA+洗澡" 匹配不到
│       "萌宠清洁护理套餐"（词面零重叠）
├── 语义召回：Two-Tower / Dense Retrieval
│   ├── query 塔 + item 塔各出一个向量，向量近邻检索（ANN）
│   ├── 优点：跨词面语义匹配
│   └── 缺点：需要训练、有召回噪声、难解释
└── 个性化召回：协同过滤（"和你相似的人买了什么"）

关键工程点：
├── ANN 索引（HNSW 等）：牺牲少量精度换毫秒级近邻搜索
├── 混合融合：加权和 / 级联（先词面后语义兜底）
└── 覆盖率：召回层最容易被忽视的指标——语义模型对冷门
    Query 的覆盖率决定兜底能力（美团三期：73.61% → 89.81%）

怎么判断好坏：
├── Recall@K（对的有没有被捞进前 K）
├── 覆盖率（多少 Query 能拿到有效候选）
└── 延迟（P99 <50ms 量级）

与 Agent 的连接（price-agent 现状）：
├── semantic_product_search = 向量 + 规则混合召回（2048 维
│   doubao embedding）——正是这层的 MVP 版
├── RAG 的 BM25 + 语义混合（α=0.7）= 同款 Hybrid Search
└── 召回评测思维：只测"能召回对的"不够，要测"对的有没有
    排在候选的前面"——这是召回→排序的桥
```

## 四、③④ 排序层（Ranking）—— 美团文章主场 ⭐

### 排序漏斗

```text
粗排：轻量模型（双塔内积）快速过滤 → 给精排减压
精排：全量特征 + 复杂模型（DNN）→ 精确打分
混排：多目标融合（CTR / 下单 / 体验权重）→ 最终列表
```

### 精排模型演进史（= 理解"为什么用大模型表征"的坐标轴）

```text
LR / GBDT（特征工程时代）
    ├── 特征：人工构造（统计特征、文本匹配特征）
    └── 瓶颈：特征构建成本高、泛化弱（美团背景痛点）
        ↓
LambdaMART / LTR（Learning to Rank）
    ├── 直接优化排序指标（NDCG）的树模型
    └── 瓶颈：仍是特征工程驱动
        ↓
DNN 排序（深度时代）
    ├── 特征交叉能力增强（美团底层融合的"特征交叉网络"）
    └── 瓶颈：语义理解还是要靠特征喂
        ↓
LLM 语义表征（美团搜索 3.0）
    ├── LLM 生成语义向量 → cosine 相似度 → 分桶/门控注入
    └── 语义建模从"特征工程"变成"表征生产"
```

### LTR 三范式（美团的升级轨迹 = LTR 演进史的缩影）

```text
pointwise（逐点）：每条样本单独打分
├── 美团一期：BCE 二分类（是否点击）
└── 局限：学"绝对判断"，不学"相对序"

pairwise（成对）：正例 vs 负例对比
├── 美团二期：InfoNCE + Triplet（难负样本对比）
└── 优势：学"哪个更好"——已深挖，见解剖文档

listwise（列表）：直接优化整个列表的排序质量
├── LambdaRank / ListNet：直接优化 NDCG
└── 工业界精排主流；美团精排模型本身应是 listwise，
    表征模型的训练目标则是 pairwise——两层各司其职
```

### 特征体系（美团三期的核心结论）

```text
统计特征（行为模式）："有某行为的用户偏好这类商品"
└── user×item 交叉统计、品类统计——靠行为日志积累
语义特征（内容理解）："Query 和商品在语义上是否匹配"
└── LLM 表征 cosine 相似度——靠模型生成
两者互补不互斥（美团：叠加效应比单独验证更强，+0.32% 订单）
```

### 语义信号的注入方式演进（美团三期）

```text
① 分桶拼接（一期）：cosine → 10 桶 → 可学习 Embedding 拼接
   ├── 优点：参与特征交叉
   └── 缺点：离散化丢连续信息
② 底层 + 顶层双融合（二期）：分桶（底层交叉）+ 原始 cosine
   （顶层 LHUC）——互补，+5bp/+3bp
③ PEPNet 门控（三期）：语义相似度调制其他特征权重
   └── 高匹配放大、低匹配抑制——+25bp，优于拼接 +18bp
```

### 排序评测指标（怎么判断排得好不好）

```text
离线：
├── AUC：判别力（美团 Q2I-Click/Order-AUC 验证表征质量）
├── NDCG：位置加权排序质量（排错前面比排错后面惩罚重）
├── GAUC：按用户分组算 AUC 再聚合（个性化视角）
└── 长尾指标：长尾 NDCG@5 / BadCase@1（体验护栏）
在线：
├── AB 实验 + AA 校验（先证明实验系统无偏，再读实验差异）
├── 漏斗指标：UV → QV → CTR → 下单率 → 订单
└── 归因案例（美团）：QV 降但 QV_CTR 升 = 减少了无效曝光
    = 曝光质量优化，不是流量损失
```

## 五、⑥ 数据闭环（数据 PM 主场）

```text
行为日志（点击/下单/未点击 1:3:6）
    → 样本构造（五元组：Q + 正例×2 + 难负例×2）
    → 特征工程（统计 + 语义）
    → 模型训练（对比学习 / 排序模型）
    → 上线 → 新行为日志

闭环中的关键数据决策（美团案例）：
├── 难负样本挖掘："同请求同商家曝光未点击"
│   → 数据侧决定了表征质量上限
├── 覆盖率治理：Query 覆盖率 81.24% → 98.92%
│   → "复用模型"≠"可直接上线"，样本分布必须重新圈选
├── 样本分布：1:3:6（下单:点击:未点击）——正负比例是设计
│   不是默认值
└── Producer→Consumer 闭环：排序信号回灌表征训练
    （= papers/06 评测→训练闭环在搜索的形态）
```

**和 CoT 质检 Pipeline 的同构（你的已有经验）：**

```text
CoT 质检                         搜索数据闭环
├── 数据流入 → 质量门控（5 层 Gate） → 交付
│                        ‖
├── 曝光日志 → 样本筛选（曝光未点击=负样本） → 训练
│                        ‖
├── 通过标准定义（每层明确判断逻辑）= 指标定义
│                        ‖
└── 质量归因（失败分布 → 修 prompt）= 指标归因（→ 修模型/特征）
```

## 六、与 Agent 的连接（为什么搜索是 Agent 的工业前身）

```text
Agent 组件              搜索对应物
├── RAG 检索           → 召回层（BM25 + 向量 Hybrid）
├── 意图路由           → Query 理解（意图分类）
├── 工具选择（选哪个工具） → 重排（哪个结果最相关）
├── 多轮上下文继承      → Query 改写 / 会话内意图延续
├── 评测（任务完成率）  → 排序评测（NDCG/GAUC）+ 在线 AB
└── 记忆 / 长期偏好     → 个性化召回（协同过滤）
```

**price-agent 的定位更新（学到这层之后的自我认知）：** price-agent 目前覆盖了"召回层"（语义召回）+"Query 理解"（意图路由）的 MVP 版，M4 Rerank 落地后补上"排序层"，就拥有了搜索系统最核心的三层骨架。

## 七、知识树连接

```text
Search 🌿 (骨架建成)
├── Retrieval ← → 召回层：词面（BM25）+ 语义（Two-Tower）+ 混合
│   └── price-agent semantic_product_search = 召回层 MVP
├── Reranking ← → 排序层：LTR 三范式 + 语义特征注入
│   └── 美团三期 = 排序层工业案例（分桶 → 双融合 → PEPNet 门控）
├── Ranking ← → 精排漏斗：粗排 → 精排 → 混排
├── Hybrid Search ← → BM25 + 向量融合（RAG α=0.7 已实践）
├── Representation Learning ← → LLM 语义表征作为排序特征
├── Evaluation ← → 离线（AUC/NDCG/GAUC/长尾）+ 在线（AB/AA）
└── 评测→训练闭环 ← → 行为日志 → 样本 → 特征 → 模型 → 新日志
```
