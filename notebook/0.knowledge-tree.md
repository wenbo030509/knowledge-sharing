### 2026-07-26/27

**A. Pipeline 深度解剖（非 CoT 专项，上升到系统设计范式）：**

- `Pipeline` ← → `DAG`：Pipeline 的数学基础是有向无环图，Stage = 顶点，数据流 = 边
- `Pipeline 质量` ← → `六大工程维度`：幂等性、断点续跑、错误隔离、可观测性、背压控制、状态管理
- `错误隔离` ← → `Dead Letter Queue`：坏数据不阻塞 Pipeline，进入死信队列单独处理
- `Pipeline 瓶颈` ← → `排队论 Bottleneck Principle`：整体吞吐量 = min(每个 Stage 的吞吐量)
- `Pipeline` ← → `Microservices`：同一思想在不同领域的应用——单元职责单一、接口契约明确、错误隔离
- `批处理 Pipeline` ← → `流式/微批/事件驱动 Pipeline`：四种工程形态，CoT 质检是批处理 + 事件驱动的混合
- `Monolith vs Pipeline` ← → `抽象原则（Abstraction）`：Pipeline 的本质是通过分解管理复杂度

**B. Pipeline 与 AI 全系统连接：**

- `Data Pipeline` ← → `Training Pipeline` ← → `Inference Pipeline`：Pipeline 贯穿 AI 系统全生命周期
- `数据质检规则有效性` ← → `训练 Loss 下降幅度`：质检的价值由模型训练效果验证
- `Quality Gate` ← → `Google TFX ExampleValidator`：工业界把数据校验作为 Pipeline 标准 Stage

**C. Python 代码与 Pipeline 的同构关系：**

- `def` ← → `Pipeline Stage`：每个函数 = Pipeline 的一个阶段，函数名 = Stage 名，参数 = 输入，return = 输出
- `Python 文件结构` ← → `Pipeline 结构`：routes/ = 输入层，services/ = 处理层，models/ = 持久化层
- `class` ← → `一组相关 def + 共享数据`：class 是更高一级的组织方式，封装相关操作和配置
- `Transformer 架构` ← → `嵌套 def Pipeline`：Attention 和 Feed Forward 都是 def，整个 Block 就是 def 调用 def
- `算子` ← → `def`：任何粒度的算子（原子操作/组合算子/Block）都是 def，差别只在内部数学复杂度

**D. 四层后端架构与 Python 关键词体系：**

- `routes/` ← → `装饰器 + HTTP 翻译`：@router.get/post 将 HTTP 请求映射到函数调用，不写业务逻辑
- `schemas/` ← → `Pydantic BaseModel + Field`：定义 API 输入输出格式，和 models 的区别是"校验 API 格式" vs "映射数据库表"
- `services/` ← → `纯 Python 业务逻辑`：全是 def，不引用 HTTP 框架，可被任何场景调用
- `models/` ← → `ORM 声明式映射`：class + db.Column() 描述表结构，不写复杂逻辑
- `db.Column / db.relationship / .query.filter` ← → `数据库操作基础词汇`
- `Depends / Query / Body / Path` ← → `FastAPI 参数注入机制`
- `print() / Traceback / NameError/TypeError/AttributeError` ← → `Debug 最小工具集`
- `函数长度 + 函数命名` ← → `Code Review 最快判断标准`

**E. Python 学习方法论：**

- `写代码五步法` ← → `Pipeline 设计思维`：纸上画图 → 数据样版 → 主流程骨架 → 逐个填 def → 跑通再拆

**A. VLM 数据合成（新业务落地）：**

- `VLM 数据管线` ← → `CoT 质检 Pipeline`：方法论同构（原始数据 → 质量门控 → 合格数据），文本 → 视频迁移复用

**B. 训练与评测链路：**

- `数据配比` ← → `Scaling Law`：数量 → 覆盖度，质量 → 信噪比，单条数据权重微乎其微但配比决定能力涨跌
- `评测回流` ← → `数据迭代闭环`：环节 6 的评测结果决定环节 1-3 采什么数据，闭环才是数据策略
- `SFT` ← → `数据质量`：teacher forcing 下每个 token 的 loss 都来自标注数据，错标直接污染训练
- `业务评测集` ← → `Benchmark 分布偏差`：通用榜是加权平均，模型换代是能力权重重新分布，A 涨 B 跌，业务依赖的 B 可能跌

**C. 基座模型 vs 业务适配（行业认知）：**

- `预训练目标` ← → `业务目标`：benchmark 分数（市场信号）vs 场景指标（业务信号），目标函数天然错位
- `能力上限` ← → `能力分布`：scaling 提升"上限" ≠ 业务依赖维度"变密"
- `模型换版` ← → `适配成本`：失配期（新基座+旧适配=行为漂移=短期回退）+ 适配债（永远追版本）+ 数据资产失效
- `模型无关数据管线` ← → `工程可复用性`：模板版本化 + 数据格式与模型解耦 = 数据资产跨版本复用
- `业务评测集` ← → `模型换版决策权`：谁掌握业务评测集，谁有换基座否决权

**E. LLM 数据集全景：**
