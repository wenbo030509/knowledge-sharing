# LLM 数据集全景：预训练、后训练、评测集与 Benchmark

> 专题梳理：LLM 全生命周期中所有数据集的定位、关系与异同。
> 一句话定位：**训练类数据回答"喂什么"，评测类数据回答"怎么知道好不好"。两者缺一不可，且必须隔离。**
>
> 建立日期：2026-08-03

---

## 一、全景图：按"用途 × 时机"分两大类

```text
训练类数据集（给模型"学"的）
├── 预训练语料（Pretraining Corpus）
│   ├── 规模：万亿级 token（文本/视频），自监督，预测下一个 token
│   ├── 任务：建立基础能力（语言、视觉常识、世界模型）
│   └── 特点：无标签、海量、只求"干净"（去重/过滤）
│
├── 后训练数据（Post-training Data）
│   ├── SFT 数据：instruction + response，教模型"怎么回答"
│   │   └── VLM 交付数据（视频+prompt+CoT+response）就是这种形态
│   ├── 偏好数据：pairwise preference，教模型"哪个答案更好"（DPO）
│   └── 奖励/轨迹数据：教模型"怎么想"（RLHF/RL）
│
└── 训练期验证集（Training Validation）
    ├── 从训练数据里切出的子集（同分布同来源）
    ├── 用途：监控训练 loss、防过拟合、选 checkpoint、early stopping
    └── 它是"训练流水线的仪表盘"，不是"考试"

评估类数据集（给模型"考"的）
├── 开发期验证集（Dev / Validation Set）
│   ├── 迭代用：模型 A vs 模型 B、调参、选版本
│   └── 传统 ML 的 train/val/test 划分里的 val
│
├── 测试集（Test Set）
│   └── 最终验收：只跑一次，跑了就作废（防止对着测试集调参）
│
└── Benchmark 数据集
    ├── 公开、标准化、跨组织可比（MMLU、Video-MME、SWE-bench）
    ├── 特点：有排行榜、发布后全网可见
    └── 风险：题目泄漏进训练集（contamination）→ 分数失真
```

## 二、最容易混淆的三个区分

### 区分 1：两个"验证集"根本不是一回事

```text
训练期验证集：从训练数据里切出来的 → 看模型"学得怎么样"（监控）
开发期验证集：评测体系里的 → 看模型"考得怎么样"（选型）

中文语境里都叫"验证集"，但一个属于训练流水线，一个属于评测体系。
```

### 区分 2：评测集 ⊇ Benchmark

```text
评测集（Eval Set）= 广义：任何用于评估模型能力的数据集
└── 内部评测集：公司自建、贴合业务、保密（防泄漏）、持续更新
└── Benchmark = 公开化的评测集：标准化、可比、有排行榜
    └── 但和业务脱节 —— "基座刷榜 vs 业务不涨"现象的根源
```

### 区分 3：训练集与评测集的隔离 = 泄漏问题

```text
核心原则：训练集与评测集必须严格互斥
├── benchmark 公开 → 预训练语料可能已包含题目 → 模型"背过答案"
├── 所以内部评测集要保密：网上搜不到 = 测的是真能力
└── 面试话术："我设计的评测集独立于训练数据，
    且不向任何模型训练环节暴露"——防泄漏意识
```

## 三、异同对照表（面试可直接用）

| 维度 | 预训练语料 | SFT 数据 | 评测集 / Benchmark |
|------|-----------|----------|-------------------|
| 用途 | 学基础能力 | 学行为模式 | 考能力对错 |
| 规模 | 万亿 token | 万～百万条 | 千～万条 |
| 标签 | 无（自监督） | 有（输入+期望输出） | 有（输入+标准答案） |
| 质量要求 | 去重、干净 | 正确 + 多样 + 难度 | 标注准 + 难度分层 + 防泄漏 |
| 使用时机 | 第一阶段 | 第二阶段 | 贯穿全流程 |
| 自身怎么评 | 无法直接评 | 用评测集评 | 用指标评（Accuracy/pass@k） |

**一条主线记住全部**：训练类数据回答"喂什么"，评测类数据回答"怎么知道好不好"。
**一句话总结**：训练集、评测集、benchmark 的区别不在数据长什么样，而在"给谁用、防什么"——**训练集防噪音，评测集防泄漏，benchmark 防过拟合**。

## 四、评测集构建：一个独立的工程师岗位（Eval Engineer）

2025-2026 年，评测工程师是独立岗位。完整工作内容：

```text
① 任务定义：测什么能力？（六类视频能力分类就是这个）
② 数据采集 + 标准答案制定：正确答案怎么定？专家？规则？LLM 仲裁？
③ 难度分层：简单/中等/难配比
   ├── 太难 → 地板效应（大家都 0 分，没区分度）
   └── 太易 → 天花板效应（大家都满分，同样没区分度）
④ 防泄漏设计：和训练集隔离、保密、随机化
⑤ 指标设计：Accuracy？pass@k？分级评分（qualified/needs_repair/discarded）
⑥ 版本管理：评测集也要版本化（防止模型过拟合到旧版 = 评测饱和问题）
⑦ 持续更新：每轮新能力 → 新增题型
```

## 五、已有资产映射（个人实践位置）

```text
已有资产
├── 质检规则定义 = 评测标准定义（5 层 Gate 通过标准）
├── Eval Set 建设（黑盒 20% 配比、长尾 + Reasoning 覆盖）= 任务定义 + 防泄漏
├── 三级分类体系（qualified/needs_repair/discarded）= 分级评分
└── 业务评测集认知 = 换基座否决权（见"基座模型 vs 业务适配"讨论）

三层评测都在工作半径内：
├── 微观：单条数据质检（Gate）
├── 中观：Eval Set（独立设计过）
└── 宏观：Benchmark 对标（理解它的局限）
```

### 面试故事升级（把"质检"翻译成"评测集构建"）

```text
❌ 旧说法："我定义了质检规则，筛出合格数据"
✅ 新说法："我独立设计了面向 CoT 数据的评测集——包含 5 层 Gate
   的分级评分体系（通过/修复/废弃三级分类），并设计了 20% 黑盒
   配比防止评测集被训练数据污染，覆盖长尾知识与推理场景。"
```

## 六、知识树连接

- `预训练语料` ← → `后训练数据`：学基础能力 vs 学行为模式，同一模型的两次投喂
- `训练期验证集` ← → `开发期验证集`：同名不同物，训练流水线仪表盘 vs 评测体系考试
- `评测集` ← → `Benchmark`：benchmark = 公开标准化的评测集子集；内部评测集保密防泄漏
- `训练集` ← → `评测集`：严格互斥，泄漏 = 分数失真
- `评测集构建` ← → `Eval Engineer 岗位`：任务定义/难度分层/防泄漏/指标/版本管理 = 独立岗位职责
- `质检 Gate` ← → `评测集`：微观（单条数据验证）→ 中观（Eval Set）→ 宏观（Benchmark）三层同构
- `评测集` ← → `Model Upgrade Adaptation`：业务评测集 = 换基座唯一决策依据（见 2026-08-03 daily）
