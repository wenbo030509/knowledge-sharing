## 工作汇报

### 新组定位

**AI 数据与安全 - 视觉理解与世界模型 - 基础模型标注组**

工作内容：VLM 视频侧需求（多视频理解）数据收集的自动化：
爬取 → 入库 TOS → 去重 → 根据视频自动撰写 prompt 及初版 CoT → 离线飞书文档串联自动填写

### 核心动作：标准文档拆解（本周工作）

通读并拆解《VLM视频-多视频理解数据收集-标准文档》，产出可执行工作要点：

```text
1️⃣ 核心目标
├── 找到"可构建多视频问答"的视频（可拆分单视频或组合多视频）
├── 围绕多段视频构建中高难度 QA
└── CoT 写清跨视频证据与对应关系

2️⃣ 能力维度体系（三层分层）
├── L1 跨视频感知：空间方位 / 计数统计 / 事件定位 / 行为理解
├── L2 跨视频对比：过程错误检测 / 时间交叉引用 / 实体匹配·状态差异 /
│   模式对比 / 功能步骤对齐
├── L3 跨视频推理：因果推理 / 假设·操作迁移 / 综合理解
└── 暂不做：叙事理解 / 时序排列

3️⃣ 操作流程
├── 网络按关键词获取"可配对"视频
├── 按维度构造问题与答案
└── CoT 格式："逐视频、逐证据段落 + 汇总结论"

4️⃣ 交付格式
├── JSON 对象：sample_id / video_tos_link_1..n / question / answer / cot
├── 剪辑与去信息干扰（打码）要求
└── 视频多样性要求
```

### 预期结果

- 选材聚焦"多视频问答可构造性"
- 出题与 CoT 可追溯（跨视频证据明确）
- 交付 JSON 字段一致，可直接入库/评测
- 为自动化探索（爬取 + 离线文档串联自动填写）提供结构化约束与模板

## 四视角提炼

- **PM 视角**：标准文档 → 可执行要点，本质是把"什么是好数据"从文档变成流程约束；自动化范围界定（初版 CoT，人工出终版）
- **算法视角**：L1/L2/L3 分层逻辑 = 感知 → 对比 → 推理的复杂度递进；多视频 QA 的"中高难度"如何量化定义？
- **工程视角**：为什么用 video_tos_link 而非网络 URL？（持久化/权限控制/去重前置）；视频去重 vs 文本去重的差异（帧级/感知哈希）；飞书文档自动填写 = 交付自动化的落地形态
- **策略视角**：暂不做方向（叙事理解/时序排列）的边界判断依据是什么？可配对视频的检索策略如何验证覆盖率？
