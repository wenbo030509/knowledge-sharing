#### 「有大规模数据清洗 pipeline 落地经验（TB 级别 tokens）」

| 现在 | 要求 | 差距 |
|------|------|------|
| 5000 条级别的手工 Pipeline | TB 级别的数据处理经验 | 规模差距无法伪造 |

**弥补动作（分两步）：**
- [ ] **第一步：理解层。** 学习 MapReduce 思想、数据分片、分布式处理的基本概念。目标是面试时能说清楚"如果数据量翻 10000 倍，我的方案要怎么改"
- [ ] **第二步：实践层。** 找一个公开数据集（如 Wikipedia 某语言 dump、Common Crawl 小样本），用 DuckDB 做本地数据清洗。数据量不需要 TB，但流程要完整（读取→过滤→去重→统计→输出报告）。重点是把 Pipeline 设计清晰，每个 Stage 有 Metrics 统计

**完成标准：** 面试被问到"你处理过多大规模的数据"，能回答"我日常处理的是数千条级别，但我理解大规模处理的核心原理，并且做过一个包含去重和 Metrics 统计的端到端清洗 Pipeline"。

#### 「理解模型训练与优化的基本原理，熟悉模型评测方法」

| 现在 | 要求 | 差距 |
|------|------|------|
| Information Bottleneck 层面 | 理解 Pretrain/SFT/RL 的数据需求差异 | 缺乏系统认知 |

**弥补动作：**
- [ ] 搞清楚三个阶段的本质区别（用 Pipeline 类比）：

```text
Pretrain：模型从海量文本中学习语言的统计规律
├── 数据需求：量大、多样、覆盖面广
├── 质量标准：去重 > 格式 > 内容正确性（这个阶段不那么在意细节）
└── 你的经验连接：你质检的 CoT 数据就是 Pretrain 的 Eval Set

SFT（Supervised Fine-Tuning）：模型学习"怎么按人类期望的格式输出"
├── 数据需求：高质量 QA 对、指令遵循样本
├── 质量标准：格式规范性 > 指令覆盖度 > 答案正确性
└── 你的经验连接：LLM Repair 就是在用 LLM 做 SFT 级别的数据修复

RL（Reinforcement Learning）：模型学习"怎么做得更好"
├── 数据需求：偏好对比数据（好的回答 vs 不好的回答）
├── 质量标准：偏好信号的准确性 >> 数据量
└── 你的经验连接：质检规则中的"人工仲裁"就是隐式的偏好信号
```

- [ ] 能用自己的话讲清楚"一段数据在 Pretrain、SFT、RL 三个阶段分别有什么质量要求"
- [ ] 了解模型评测的基本方法：Benchmark、LLM-as-Judge、Human Evaluation

**完成标准：** 面试时被问"你对模型训练了解多少"，能讲清楚三段训练的数据需求差异。

## 三、自驱项目计划（弥补"0 项目经验"到"有可展示项目"）

### 项目一：Agent 能力评测 Pipeline ⭐⭐⭐（最重要）

**对标岗位：** 预训练数据工程师（Agent 方向）、通用 Agent 数据 PM

**项目背景：**
你在日常使用 Claude Code 处理数据任务。你设计一套自动化评测方案，量化 Claude Code 在不同任务类型上的表现。

**技术栈：** Python + pandas + 你自己的评测逻辑

**执行步骤：**

```text
Week 1：定义评测体系
├── [ ] 定义 5 个评测维度，每个维度 0-3 分评分标准
├── [ ] 设计 10 个测试任务（覆盖数据处理、代码生成、Debug、多轮交互）
└── [ ] 写一个 JSON Schema 定义测试用例格式

Week 2：搭建 Pipeline 骨架
├── [ ] 写 run_eval.py：读取测试用例 → 调用 Claude Code → 收集输出
├── [ ] 写 score.py：对每个输出按 5 个维度打分
├── [ ] 写 report.py：生成评测报告（按维度、按任务类型统计）
└── [ ] 跑通第一个测试用例

Week 3：批量评测 + 分析报告
├── [ ] 跑完 10 个任务
├── [ ] 人工验证评分是否合理（校准评分规则）
├── [ ] 写分析报告：哪个维度最弱？哪种任务最容易失败？
└── [ ] 推送到 GitHub

Week 4：迭代 + 完善
├── [ ] 根据分析报告，提出 3 条数据策略建议
├── [ ] 更新 README（项目介绍 + 使用方法 + 结论）
└── [ ] 写一篇项目总结（面试时讲的故事）
```

**产出物清单：**
- [ ] GitHub 仓库：`agent-eval-pipeline`
- [ ] 包含：评测代码 + 10 个测试用例 + 评测报告 + README
- [ ] 一篇项目总结（可放在 `projects/agent-eval-pipeline.md`）

**简历子弹点：**
> "独立设计并实现了 Agent 能力多维度自动化评测 Pipeline，覆盖任务完成度、过程效率、指令跟随、错误恢复、代码规范 5 个评测维度，基于 10 个真实场景任务产出量化评测报告，并推导出 3 条数据策略优化建议。"
