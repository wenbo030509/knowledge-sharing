## 二、故事总览（30 秒版本）

### 1. 字节 · CoT 质检 Pipeline ⭐⭐⭐（核心故事）

> 我在字节独立设计了 CoT 数据的多层级联分类质量门控系统：5 层 Gate（格式 → 内容 → LLM 修复 → 标签纠错 → 分布校验），处理 5,497 条数据，输出 4,346 条合格（79.06%），交付算法团队纳入预训练 Eval Set。打通众包 → 质检 → 修复 → 交付全闭环。

### 2. 字节 · VLM 多视频理解数据生产 ⭐⭐⭐（核心故事·进行中）

> 我在字节负责 VLM 多视频理解数据的生产标准与采集合成自动化。拆解标准文档，梳理 L1 感知、L2 对比、L3 推理三层能力维度体系，定义 JSON 交付格式与"逐视频逐证据"CoT 结构，推进关键词爬取 → TOS 入库 → 去重 → 自动生成 prompt 与初版 CoT 的自动化管线。

### 3. 百度 · 一键百看投放 Agent ⭐⭐（Agent 产品故事）

> 我在百度主导了品牌广告投放 Agent 的全链路设计：统一资产模型、物料迁移 Agent（迁移成功率 92%）、语义匹配召回、任务编排框架。投放链路操作步骤减少 60%，单物料时效小时级 → 分钟级，人力成本降低 98%。

### 4. 第四范式 · MaaS + 军事 Multi-Agents ⭐⭐（技术产品化故事）

> 我在第四范式先后参与两个项目：①航空机务私有化 MaaS——LoRA 微调产品化（场景模板 + 专家评测）、多源文档 RAG（多路混合检索）、意图识别多智能体路由（5 类助手）、"自动化测试集 + 机务专家校验"双模评测；②Manus 引爆后跟进的军事领域 Multi-Agents 产品——深度体验调研 Manus，参与产品设计与开发，持续迭代到离职。

### 5. Price-Agent · 商品对比智能助手 ⭐⭐（自驱 Agent 项目）

> 我独立设计了一个 AI 比价搜索 Agent。核心是四类意图路由架构 + 手机品类 17 字段数据模型 + 7 阶段分层评测体系（158+ 用例），评测结论驱动了归一化规则、语义权重（α=0.7）、追问上限等关键迭代。

### 6. Kaggle · 广告欺诈检测 ⭐（数据能力硬证据）

> 我在 Kaggle 处理 2 亿条点击数据，针对 1:33 极度不平衡问题，设计 IP 分桶分布式处理 + 四类统计特征，LightGBM + 网格搜索 + Early Stopping，验证集 AUC 0.96，欺诈召回率 93%。

### 7. 第四范式 · 评测缺失的教训（复盘视角，并入故事 4）

> 我在第四范式参与 ToB 垂类模型交付时亲眼见过反面教材：没有评测体系的微调 = 盲人摸象——没有 baseline、没有测试集、没有 badcase 分析，模型效果无法量化也无法迭代。这段经历让我理解了 Evals 的不可或缺性，直接塑造了我在字节主动做质量验证的方向。

**隐藏规律（这个叙事最值钱的两句话）：**

① 行业每次发现"上一层解决不了问题"，重心就往上游移一层——模型不够好 → 微调+编排补；编排太死板 → Agent 自主性补；Agent 不稳定 → 评测体系补；评测发现天花板 → 数据生产补。**我的经历排列顺序恰好等于这个迁移顺序。**

② 我追的东西一次比一次更本质：MaaS 学的是"被验证的旧打法"（滞后 18 个月）→ 军事 Multi-Agents 追的是"概念风口"（Manus 一引爆就跟进，但形态是垂直 POC）→ 百度补的是"工程现实"（行业收敛后的 Harness 形态）→ Price-Agent 追的是"方法论"（评测 + 数据飞轮）→ 字节站在"第一性"（数据/评测最上游）。**从学旧打法到站上共识瓶颈，这条追赶曲线本身就是一个可讲的故事。**

### 7.2 口述版讲解

**30 秒版：**

> 过去两年我经历了 AI 落地的完整链条：从微调加编排的企业 chatbot（第四范式），到 Manus 引爆后第一时间跟进的垂直领域 Multi-Agents 产品（第四范式后期），到 Agent 嵌入 B 端业务的工程化改造（百度），到完整的 Agent 产品设计与评测实践（自驱项目），再到模型训练上游的数据与评测工程（字节）。这条路径跟着行业的重心走——模型 → 应用 → Agent → 数据与评测，而且我追的东西一次比一次更本质：从旧打法、概念风口，到工程现实、方法论，最后站在数据第一性的最上游。我想做评测驱动的策略产品，就是这些经历的交集收敛出来的。

**2 分钟版：**

> 我讲一下我的经历为什么是连成一条线的。第一段在第四范式（2024.10-2025.8），前半做航空机务的 MaaS 平台——LoRA 微调、Dify 编排、RAG 知识库，行业 2023 年就成熟的企业级打法，我晚于前沿，但完整走了一遍被验证的链路。后半正好赶上 Manus 引爆：我们第一时间深度体验和调研了 Manus，然后启动军事领域的 Multi-Agents 产品——老板的想法是做军事领域的 Manus 服务客户，我参与产品设计与开发，一直迭代到离职。这是我第一次从概念风口跟进 Agent 产品。第二段在百度，把 Function Calling 的 Agent 嵌进品牌投放平台做迁移提效——用固定表单约束输入换确定性，这是行业 2024 年收敛的工程化 Agent 形态，我学到的是 Agent 的工程边界。第三段是我自己的 Price-Agent——多链路、评测集、回溯归因、数据飞轮，完整跑了一遍 Agent 产品化的方法论，这对应行业 2025 年最大的命题：Agent 怎么证明自己好用——到这段我已经和行业同频。第四段在字节，做模型训练前的数据处理、质检、评测自动化——行业重心已经移到"数据是第一性瓶颈"，我追到了最上游。这四段不是四个方向，是同一条价值链上连续的节点，而且我追的东西一次比一次本质：旧打法、概念风口、工程现实、方法论、第一性；我的主线——评测和数据——在每一段都出现，只是海拔越来越高。

### 7.3 个人链路的局限：与真实行业演进的差距

**行业是多线并行的，我走的是其中一条支线：**

```text
AI 行业的并行线（2023-2026）：
├── 模型线：GPT-4 → 4o → o1/o3 → Claude 系     ← 我几乎全程只是使用者
├── 开源线：LLaMA → DeepSeek 开源推理           ← 我 2026 才在字节接触
├── 多模态线：GPT-4V(2023) → 视频理解 → 世界模型 ← 我 2026 才切入
├── Agent 线：AutoGPT → Coding Agent(Devin) → Agent OS ← 我只接触 B 端支线
└── 数据/评测线：MMLU → SWE-bench → τ-bench → RL 数据 ← 我走的是这条
```

**每阶段我做的 vs 同期行业正在发生的：**

| 阶段 | 我在做的 | 同期行业正在发生的（我没接触的） |
|------|---------|-------------------------------|
| 2024.10-2025.2 | 企业 chatbot 套件（行业 2023 年的成熟打法） | o1 推理模型（2024.9）、Devin 编码 Agent、MCP——行业已进入 Agent 化 + 推理时代 |
| 2025.3-2025.8 | 军事 Multi-Agents（Manus 垂直复制，POC） | Manus 引爆通用 Agent 热潮；行业同步开始工程化收敛（Building Effective Agents 就是这前后） ← 概念同频 |
| 2025.8-2026.4 | B 端固定表单 Agent（行业 2024 年的收敛形态） | Agent 评测体系铺开（τ-bench、SWE-bench）、Claude/GPT 新一代 Agent 能力 |
| 2026 | 数据生产 + 评测自动化 | RLVR 数据军备竞赛、后训练数据第一性共识 ← 基本同频 |

**滞后性规律（要诚实承认）：**
- MaaS（2024.10-2025.02）：滞后约 **18 个月**——2025 年初还在做 2023 年的 chatbot 打法，同期行业已经在 o1 / Devin / MCP
- 军事 Multi-Agents（2025.03-2025.08）：**概念同频**——Manus 一引爆就跟进；但只追到了概念层，工程形态是垂直 POC，工程收敛是后来在百度补的
- 百度（2025.8-2026.4）：滞后约 **6-12 个月**——做的是 2024 年收敛的工程化 Agent 形态，同期行业在铺评测体系
- Price-Agent（2026）：与行业同频——评测 + 数据飞轮正是当时的核心命题
- 字节（2026-）：站在行业共识瓶颈上——**滞后已经追平，这是当前最大的时效性优势**

**差距的正确用法（面试话术）：**

> 我的经历是行业演进的抽样，不是全貌——行业是多线并行的，模型、多模态、开源生态这些线我只是使用者，没有建设经验。但这个抽样恰好覆盖了价值链从应用到训练的关键节点，而且因为滞后，我学到的都是被验证过的形态，不是泡沫。我知道自己没做过什么，这让我对能做什么的判断更保守、更靠谱。

### 7.5 防御问答

**追问：你每段都不长，是不是都不深？**

> 深度不在单段，在主线：评测和数据这两件事在我四段经历里全部出现且逐段加深——百度做 Badcase 分类、自驱项目建评测集和回溯、字节做评测自动化和规范设计。我在同一条主线上挖了两年，只是换了四个不同海拔的场景。

**追问：你从 Agent 回到数据，是走回头路吗？**

> 不是回头，是闭环：先做了两年"用模型的人"，理解了真实场景里模型的短板在哪里，现在做"决定模型吃什么的人"。数据工程师最缺的业务直觉——知道什么样的数据在什么场景下有用——正是前两段经历给我的。
