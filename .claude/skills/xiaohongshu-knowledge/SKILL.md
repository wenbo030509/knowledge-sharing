# Xiaohongshu Knowledge (小红书知识提取)

给一条小红书分享链接（含 `xhslink.cn` 短链），提取帖子的正文文字与图片内容，并把藏在图片里的文字识别出来、清理后汇总成可用的知识。适用于**无需登录就能打开的公开笔记**。

## 核心设计：抓取 → 下载图片 → agent 看图判相关性 → 相关留/无关弃

主路径是**你（当前会话的多模态模型）用 Read 逐张看下载到本地的图片**，判断每张图与帖子主题是否相关：相关的保留并转写进正文，无关的直接舍弃（不落盘、不进 `images/`）。脚本 OCR 只是**无视觉会话时的兜底**。

> **为什么主路径是"agent 看图"而不是"脚本 OCR"（跨设备/跨 agent 的关键）**：
> 本 skill 会被不同设备、不同 agent runtime 调起。脚本 OCR 的 model 引擎依赖宿主注入
> `ANTHROPIC_*` 环境变量、本地回退依赖 macOS `swiftc` / `tesseract`——这些在异构环境
> （不同厂商 key、非 Claude Code runtime、Windows/Linux）**都不保证存在**，一旦缺失就静默降级到空。
> 而"当前会话的 agent 本身就是多模态模型"这个能力，是**任何视觉 agent 都自带**的，零配置、跨平台。
> 所以：**下载靠脚本（确定性），识图 + 判相关性靠 agent（普适性）**。

### 第一层（主）：下载图片 → agent 逐张看图 → 判相关性 → 相关留/无关弃

脚本位于仓库根的 `src/` 目录，以仓库根为工作目录运行（当前目录不是该仓库则先 `cd` 过去）。先只下载、不 OCR：

```bash
src/xhs_fetch.py <链接> --out <输出目录>
```

脚本会：解析短链 → 抓 SSR 数据 → 下载全部图片，在 `<输出目录>` 写出：
- `note.json` — 标题、正文(desc)、作者、标签、图片数、图片路径
- `img_*.jpg` — 保序下载的图片（与帖子顺序一致）

然后**你用 Read 逐张读 `img_XX.jpg`**，对每一张做两件事：

1. **判断与帖子主题的相关性**（视觉判断，别只看有没有字）：
   - **无关图 → 舍弃**：纯风景/人像/背景/表情包/logo/二维码，无有效文字且与主题无关 → 不转写、不进 `images/`，交付时用一句话说明已舍弃（不静默丢失）。
   - **有效图 → 保留**：截图、幻灯片、笔记、带文字说明的图、与主题相关的示意图 → 保留并转写。
2. **对保留的图忠实转写**：表格图 → Markdown 表格（行列不错位）；流程图 → 用 `→` 还原步骤与箭头文字；截图 → 转写可见字段/数值；看不清的字标 `[?]`，绝不为顺滑而编造知识点。

### 第二层（兜底，仅在当前会话无视觉能力时用）：脚本 OCR

只有当当前会话模型**不支持视觉**（Read 图片返回 Unsupported）时，才降级加 `--ocr` 用脚本 OCR 兜底：

```bash
src/xhs_fetch.py <链接> --ocr --out <输出目录>
```

- `--ocr` 调用共享模块 `src/img_ocr.py`（`--ocr-engine model|vision|tesseract`，默认 `model`=视觉 API，需宿主提供 `ANTHROPIC_*`；失败自动回退 macOS Vision → tesseract）。产物多一个 `ocr_raw.txt`。
- ⚠️ OCR 环境不一定具备（见上方说明），且 OCR 文本很脏（断行/切词/丢表格结构）——**只是不丢字的兜底对照物，绝不直接当结果交付**。
- 用 OCR 兜底时：以识别文本为依据做清理还原，把必须看图确认的段落（手写/密集表格）标注「⚠ 待视觉会话复核」；无视觉时无法判相关性的图，**保守保留并标注待复核**，恢复视觉能力后再按第一层判定与更正。

## 三种情况合并规则（用户核心需求）

1. **正文与图片内容相同** → 只保留一种形式。
2. **知识在正文，图片无关**（装饰图/风景/表情）→ 只保留正文，图片丢弃。
3. **知识在图片，正文只是补充/备注** → 正文仅在包含图片没有的事实时才保留，否则丢弃；对每一张有效图做识别，全部汇总。

## 交付格式

输出一份干净的结构化 Markdown：帖子标题与链接、提取出的正文/图片内容，并清楚区分"正文保留部分"与"图片汇总内容"；对被丢弃的形式简要说明一句（让用户知道没有静默丢失）。**保留关键表述的原意，不要为了顺滑而把知识点改写掉。** 同时给出脚本产物所在的输出目录。

## 落盘：遵循知识库文档体系

抓取并整理完小红书帖子后，要像微信文章一样落盘到知识库。以下路径以 `knowledge-sharing` 仓库根为基准；若当前工作目录不是该仓库，先 `cd` 过去（或用仓库绝对路径）。

### 第 4 步：落盘

```text
papers/NN-来源-主题/
├── 原文.md      ← 清理后的完整内容（正文 desc + 合并后的图片文字；忠实内容，不增删）
├── 笔记.md      ← 精读笔记（格式见下）
└── images/      ← 承载内容的有效图（截图/幻灯片/带文字说明的图）
```

- `NN` 是下一可用编号（当前 `papers/` 排到 07，下一个通常是 `08`）。
- `来源` 是机构名/博主名（如 anthropic、meituan、openai、deepseek；小红书用作者昵称，取自 `note.json` 的 `author`）。
- `主题` 简洁（如 `algorithm-role-definition`、`llm-shouji`）。
- 若帖子属于已有专题（如美团技术视频系列），也可放 `notebook/` 对应专题文件下，用判断力。
- `原文.md` 只忠实保留提取到的内容，不增删；图片里有但 OCR 没抓准的，以图为准写进原文。

### 笔记.md 格式

参考 `papers/01.anthropic-agent-evals/笔记.md` 与 `papers/02.meituan-agent-evals/笔记.md`：

```text
# 精读笔记：<文章标题>

> 来源 / 阅读日期 / 重要性（⭐⭐⭐ 标准：是否对标 Agent PM 岗位核心能力）

## 一、文章在讲什么（30 秒版本）   ← 一段话
## 二、核心观点（带面试说法）       ← 每个观点配【面试说法】，技术术语保留英文，树形结构展示层级
## 三、与相关文章的对比（如有）     ← 和已有 papers/ 目录里的文章做重合/差异对比
## 四、面试故事模板                 ← 结合用户项目经验（CoT 质检/评测 Pipeline）
## 五、知识树连接                   ← 记录 knowledge-tree.md 里的节点连接
## 六、待深挖方向                   ← 勾选列表
```

### 第 5 步：同步文档体系（三个文件，漏一个索引就过期）

1. `README.md` — `papers/` 目录树加新目录。
2. `CLAUDE.md` — 第七节文档体系的 `papers/` 目录树加新目录。
3. `notebook/0.knowledge-tree.md` — 在「知识连接记录」对应日期下加连接，格式：`- \`节点A\` ← → \`节点B\`：连接说明`。

## 已知坑（小红书专属，踩过的记录）

1. 内置抓取/网页工具对小红书常失败 → 第一反应就是 `curl` + 解析 SSR，不要浪费调用；短链 `xhslink.cn` 必须先解出真实 URL（带 `xsec_token`）。
2. `window.__INITIAL_STATE__` 里含字面量 `undefined` → 必须先清洗成 `null` 再 `json` 解析，否则报 `Expecting value`。
3. 图片 CDN（`sns-webpic-qc.xhscdn.com`）在本机校验证书失败（自签证书链）→ 用关校验下载，脚本已处理。
4. 正文与图片常常冗余：正文=图片内容时只留一种；知识在图片、正文只是备注时，图片才是主体。
5. 很多图片是装饰（风景/人像/表情），且可能完全无字 → 必须用视觉判读，别只看 OCR 是否出字。
6. 页面要求登录/触发风控（拿不到 `noteDetailMap`）→ 如实说明，不要编造内容。
7. 通用 HTML 转 Markdown 工具不适用于小红书（无 `<article>`，正文在 SSR 的 `noteDetailMap`）→ 必须走「解析 `__INITIAL_STATE__` + OCR」这条专门链路。

## 约束与边界

- 若页面要求登录或触发风控（拿不到 `noteDetailMap`），如实说明，**不要编造内容**。
- 图片 CDN（`sns-webpic-qc.xhscdn.com`）在本环境可能校验证书失败，脚本已用关校验方式处理。
- 脚本处理"提取"，你的职责是"清理、理解、格式化"——不要脱离脚本产物重新发明事实。

## 注意事项

- **跨平台命令约定**（本 skill 在不同设备/OS 上被调起，命令按你的环境适配，不要照抄）：
  - `src/xhs_fetch.py <链接>` 直接执行依赖 shebang；更稳妥用解释器显式调用——`python3 src/xhs_fetch.py`（Windows 上通常是 `python src\xhs_fetch.py`，先 `python --version` 确认）。
  - 首次跑若报缺依赖 → 脚本仅用标准库 + 可选 `certifi`，一般无需装；`--ocr` 的 model 引擎需宿主 `ANTHROPIC_*` 环境变量。
  - 含中文/空格的输出目录路径加引号；路径分隔按当前 shell 语法。
- `src/xhs_fetch.py` 的 OCR 编排在共享模块 `src/img_ocr.py`（`ocr_images()`：默认 model 引擎=视觉 API，失败回退 macOS Vision → tesseract）。vision 层首次运行会自动 `swiftc` 编译同目录 `img_ocr.swift`（仅 macOS）。微信文章技能（wechat-article）复用同一模块。
- 图片按 `img_00.jpg` 顺序命名，与帖子里图片顺序一致；汇总时可按此顺序还原叙事。
