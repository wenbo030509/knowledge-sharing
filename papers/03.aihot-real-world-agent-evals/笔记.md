# 精读笔记：说一个反常识的真相，Agent 如今在真实工作场景的成功率依然很低

> 来源：卡兹克（AIHOT 大模型排行榜作者），微信公众号
> 阅读日期：2026-08-20
> 重要性：⭐⭐⭐ 真实业务场景评测的一手行业数据 + 与 Anthropic/美团评测方法论交叉验证。面试里讲"模型能力强 ≠ Agent 业务效果好"的归因，全靠这篇的数据支撑。

---

## 一、文章在讲什么（30 秒版本）

作者翻遍现有评测集后发现：**"真实工作任务"类评测集极其稀缺**——市面上榜单（LiveBench、DeepSWE 等）都在测能力维度（Coding、数学、浏览器操作），缺的是"给模型一份真实工作，从头干到尾，看最终交付效果"的评测。用上周开源的阿里国际站 RealReplicaBench（电商真实任务，107 题）举例：**最先进的模型通过率也只有 60.75%（Claude Opus 5），大部分模型不到 50%**——和 Coding 领域 70%+ 的体感完全相反。结论：**"会解题"和"会工作"之间还隔着遥远的距离；真实工作琐碎、混乱、没有标准答案，这才是 Agent 的终极考场。**

## 二、核心事实（面试直接引用的数据）

### 2.1 RealReplicaBench（阿里国际站 Accio，2026-08 开源）⭐

```text
评测集构建漏斗（这是评测集生产管线的完整案例）：
├── 160 万条完整对话（Accio Work 电商 Agent 真实使用记录）
├── → 20 万条工作流
├── → 约 2000 条商业价值高的
└── → 107 个任务（按"可复现性 + 结果可判定性"筛选）

覆盖场景：供应商采购、商品发布、店铺经营、订单对账、
国际物流、售后争议、跨平台月度对账……

典型任务示例：
├── 上线定制瑜伽垫：从发品计划+3 家供应商报价+实拍图里，
│   找指定供应商，填类目/销售国家/差异定价/描述，挑正确商品图上传
├── 东莞→达拉斯电子产品运输：30 天限制下计算保险/清关/海关担保/
│   平台费，找最低成本路线，仿真货代平台订舱+货件验证
├── 退货争议处理：把订单记录、物流扫描、仓库质检、客户对话、
│   照片、平台政策、截止时间全对起来，逐单决策（退款/部分退款/申诉/补证据）
└── 跨平台月度对账：天猫/京东/拼多多三套格式清洗到一张表，
    统一 SKU 和状态，核对发货结算差异，算收入/成本/佣金/利润

难度设计（体现"人类世界的混乱性"）：
├── 项目需求散落在 10 封邮件里，中途改过数量和要求
├── 混入 4 组名字相似但不同的供应商（联系人/邮箱/域名/显示名称全变）
└── 需综合工厂地址、电话、银行收款人、出口许可证交叉核对

评分机制：23 组、42 项结果检查（直接查邮箱/草稿/日历/JSON 最终状态）
├── 全部通过才得 1 分，差一项就是 0 分 —— 没有过程分
└── 理由："真实电商差一步可能就丢了单子，这才是真实的商业世界"
```

### 2.2 成绩（PI 开源 Harness 框架下）

```text
Claude Opus 5    60.75%（107 完成 65）—— 唯一过及格线
Qwen 3.8 Max    49.53%（并列第三）
DeepSeek V4 Pro  49.53%（并列第三）
大部分模型 <50% → 107 个任务有一半以上全失败

换成 Accio 自家框架跑：通过率 50% 以上的模型从 2 个 → 6 个
→ Harness（框架）对真实任务通过率影响巨大
```

### 2.3 对比：Coding 任务（DeepSWE，2026-05 发布）

```text
113 个任务：真实开源仓库里独立完成复杂跨文件软件工程改动
（mini-swe-agent 框架跑）
头部模型通过率 70%+

结论：Coding 体感"大杀四方" vs 真实业务任务"几乎不及格"
```

### 2.4 其他真实任务评测集（佐证这是普遍现象）

| 评测集 | 出品方 | 任务 | 最好成绩 |
|--------|--------|------|---------|
| E-Bench | 腾讯混元+清华+东南大学 | 323 个任务：王者荣耀/QQ音乐/腾讯会议真实操作 | Kimi-K3 Avg@3 73.79%；但 3 次全对仅 58.82%，11 个模型稳定性指标全 <60% |
| VibeLifeBench | 小红书 | 200 个持续数周的生活任务（职业/健身/租房/购物/差旅 10 领域） | Claude Opus 5 avg@3 仅 32.5% |
| RealReplicaBench | 阿里国际站 | 107 个电商任务 | Claude Opus 5 通过率 60.75% |

> 注意：三套基准任务、指标各不相同，不能横向比较，但一致指向——真实世界任务上大模型表现还有极大进步空间。

### 2.5 作者的观点

```text
1. 纯靠模型公司不够，需要所有厂商一起努力（Accio 承诺持续提炼真实
   工作任务，滚动更新开放评测集——因为厂商做 Agent/模型路由，
   模型强了客户价值才最大化）
2. 这些评测集偏研究、更新不及时 → 作者计划自己搭环境跑，保持更新
3. 金句："在 AI 的世界里，会解题，和会工作，中间确实还隔着
   一些比较遥远的距离"
```

## 三、与已有知识的交叉验证（本篇最大价值）⭐

### 3.1 与 Anthropic《Demystifying evals》的对照

| 维度 | Anthropic 的说法 | 这篇文章的实证 | 启示 |
|------|-----------------|---------------|------|
| 评分粒度 | 观点 6：好的评测不是二元的，支持部分得分 | RealReplicaBench 故意"全有或全无"，无过程分 | 任务粒度决定评分粒度：**单步任务适合部分得分；端到端商业任务（一步错就丢单）适合全或无**。Anthropic 面向开发场景（Agent 写代码），阿里面向交易场景（Agent 做生意），容错率不同 |
| 非确定性 | pass@k / pass^k | E-Bench 的 Avg@3（73.79%）vs 3 次全对（58.82%）是 pass@k/pass^k 的工业实例 | 直接引用：稳定性指标 11 个模型全 <60%，说明"能做对一次"和"每次都能做对"差距巨大，面向客户的 Agent 必须看后者 |
| Harness 的作用 | "评估一个 Agent = 评估框架 + 模型协同工作" | PI 框架 2 个模型过 50% → Accio 框架 6 个 | 教科书级验证：同一个模型换 Harness 通过率大幅变化。面试里这个证据链非常强 |
| 任务来源 | 8 步路线图：从手动测试/真实失败场景开始 | 160 万对话 → 20 万工作流 → 2000 → 107 的漏斗 | 工业界真实的任务集构建管线，比 Anthropic 的抽象建议更具体 |

### 3.2 与美团图灵评测方法论的对照

| 维度 | 美团的说法 | 这篇文章的实证 | 启示 |
|------|-----------|---------------|------|
| 搭桥 | 业务指标 ↔ 桥梁指标 ↔ 能力指标 | RealReplicaBench 就是"桥"本身：评测任务=真实业务工作 | 真实任务评测是弥合"模型能力提升没带来业务收益"鸿沟的桥梁指标形态 |
| 数据飞轮 | 采集→清洗→评测→质检→归因，Good/Bad Case 喂养 | Accio 的评测集构建就是标准数据飞轮，且公开承诺滚动更新 | 评测集本身就是产品，需要持续运营 |
| 评测 vs 现实 | 追求人机一致、规模化 | 阿里也承认：实际生产是人+Agent 协同，全自动化评测下通过率会更低 | 评测是全自动的严格版，真实世界有 HITL 兜底 |

### 3.3 连接你已有的知识树

```text
Cascading Classification 🌳 ← → 全有或全无评分：商业任务的 Gate 是串联的，
                               一环失败整体失败——和质检 Gate 同构
Judge Model 🌱 ← → 结果检查（42 项）：检查最终状态而非路径，和 Anthropic
                     "评分针对成果不是路径"一致（但更严格）
Benchmark Design 🌿 ← → 真实任务评测集：稀缺 = 蓝海 = Agent PM 的机会
```

## 四、面试故事模板

### 故事 1：为什么模型强 ≠ Agent 业务效果好（行业认知题）

> "我最近看了阿里国际站开源的 RealReplicaBench——107 个电商真实任务，从 160 万条对话里筛出来的。最先进的模型通过率 60.75%，一半以上的模型不到 50%，和 Coding 榜单 70%+ 的体感完全相反。同一个模型在 PI 框架下和 Accio 自家框架下通过率能差一个档位。这让我对'模型能力'和'业务效果'的关系有了准确认识：能力榜单测的是上限，真实业务测的是在混乱数据、多步操作、零容错下的稳定交付——中间隔着 Harness、任务设计、人机协同一整层。"

### 故事 2：评测集是怎么生产出来的（评测集生产管线）

> "RealReplicaBench 的构建漏斗是：160 万条真实对话 → 20 万条工作流 → 2000 条高商业价值 → 107 个可复现可判定的任务。这个漏斗本身就是我理解的评测集生产管线：从海量真实使用记录里沉淀任务，再用可复现性和结果可判定性过滤。和我做 CoT 质检的 Pipeline 逻辑一致——先有数据，再定标准，用机器可检查的规则替代主观判断。"

### 故事 3：非确定性是面向客户的 Agent 的生死线

> "E-Bench 测了 11 个模型：Avg@3 最好 73.79%，但 3 次全对只有 58.82%，11 个模型全都没过 60%。这就是 Anthropic 说的 pass^k——面向客户的 Agent 不能靠'多试几次总有一次对'，用户要的是每次都对。真实业务评测把这条暴露得很彻底。"

### 故事 4（结合字节实习）：真实任务评测是 Agent PM 的蓝海

> "目前真实工作任务评测集寥寥无几，且偏研究、更新慢。行业缺口意味着：谁能把真实业务任务持续提炼成评测集，谁就掌握了 Agent 迭代的方向盘。这正好是我实习在做的事——把业务侧的高价值任务沉淀成可判定的评测标准。"

```text
Benchmark Design 🌿 ← → 真实任务评测集：业务桥指标的最佳形态（稀缺=蓝海）

```
