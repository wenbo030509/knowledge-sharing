# 精读笔记：为什么 1T 模型 Agentic RL 不能用 pass@k 筛数据

> 来源：小红书「小red同学」（美团 M17，code/life agent 中/后训练）/ 阅读日期 2026-09-04 / 重要性 ⭐⭐⭐
> （⭐⭐⭐ 理由：直接命中「评测驱动数据策略」岗位核心——它把"被动筛数据 vs 主动按 gap 造数据"讲透，
>  正是 AI 数据策略 PM 工作闭环的另一独立印证，且给出可直接进面试的 pass@k 五点缺陷弹药）

## 一、文章在讲什么（30 秒版本）

传统 RL 数据筛选用 pass@k：让 SFT 模型对全量候选数据做 k 次 rollout，取成功率居中（k/3~2k/3）的"甜点区"样本做 RL。作者指出这套方法在 1T 大模型 + 大数据规模下有五个致命问题（算力浪费、难度漂移、reward 噪声、自我循环、目标错位），主张换一条路：**从目标 benchmark 暴露的能力缺口出发，对失败样本做能力归因，定向构造与 benchmark 同分布、可验证低噪声的数据再做 RL**——即"模型弱点驱动"替代"模型能力驱动"。

## 二、核心观点（带面试说法）

1. **pass@k 的本质 = 用"模型当前成功率"当难度代理信号**
   [面试说法] 它是个代理目标（proxy），而代理目标有三宗罪：贵（要先生成才知道难度）、
              会漂移（难度随训练变化）、有噪声（judge 不稳）。用代理目标筛数据，
              筛的是"模型自认为的边界"，不是"benchmark 真正需要的能力"。

2. **五点缺陷（可拆开逐条讲，面试高价值）**
   ├── ① 算力浪费：160 万条 rollout 里大量是错误轨迹，最终不进训练 → 算力烧在生成垃圾上
   ├── ② 难度漂移：step 0 的中等题 step 16 变简单 → 甜点区过时 → 要反复重筛，成本超过 RL 本身
   ├── ③ reward 噪声：无确定性 verifier 的任务靠 LLM judge，一致性差 → "成功率居中"可能只是 judge 抖动
   │        ★ 直接呼应我 CoT 质检里的 AA 校验 / judge 人机一致性 Kappa
   ├── ④ 自我循环：模型按自身能力选题、再用选出的题训练自己 → 已会的强化、不会的被排除 → 能力模式收缩
   └── ⑤ 目标错位：候选分布≠测试分布时，pass@k 挑出的是 benchmark-OOD 能力，不是目标缺失能力

3. **替代方案：benchmark 能力缺口驱动的定向构造（本文正向主张）**
   [面试说法] benchmark 失败样本 → 能力归因+错误分类（知识缺失/推理错误/边界条件）
              → 围绕缺口定向构造同分布数据 → 可验证低噪声 reward → 定向 RL → 回 benchmark 看涨点。
              关键差异：只分析"新失败样本"，不重筛整个通用池——把 O(全量×k) 的成本降到 O(失败样本)。

4. **一条经验数字（可当锚点记）**
   [面试说法] benchmark 上 pass@3 与 pass@1 相差约 10 个百分点时，针对性 RL 后约可提升 16 个百分点
              ——pass@k gap 大 = 有能力但不稳定 = RL 有空间，这是"该不该定向 RL"的决策信号。

## 四、面试故事模板

> 被问"你怎么看 RL 的数据筛选"或"评测和数据怎么联动"时：
>
> "有一种常见做法是 pass@k：对全量候选数据做 k 次 rollout，取成功率居中的甜点区做 RL。
> 但我认为大规模下它有本质问题——它用'模型当前成功率'当难度代理，而这个代理贵、会漂移、有噪声，
> 还会让模型只在自己已有能力附近打转（自我循环），更关键的是它筛的目标和最终评测目标可能错位。
>
> 我更认同从 benchmark 能力缺口反推：先对失败样本做能力归因和错误分类，再围绕缺口定向构造同分布、
> 可验证的数据。这跟我做 CoT 质检 / VLM 靶向 SFT 的思路一致——都是'先归因定位到具体能力短板，
> 再定向补数据'，而不是笼统地筛或加。而且只分析新失败样本、不重筛整个池，成本可控得多。"
